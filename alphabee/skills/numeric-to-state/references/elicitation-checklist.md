# 追问清单（自然语言 → 规格）

按顺序核对。每项标注 **可推断 / 必问**，以及缺失时的推荐问法。原则：可推断的先给理解让用户确认；
校准类参数必须问，用户授权默认时要在交付物里列出假设。

## 1. 轴（factors）

- [ ] 有哪些指标参与判断？（**可推断**：从用户描述里提取）
- [ ] 每个指标的输入是**方向分**（已在 `[-1, 1]`）还是**原始量**（PE、增速、收益率）？（**必问**）
  - 原始量 → 需要先定转换：`saturate(v, scale)` 还是 `log1p_saturate(v, ref)`，`scale/ref` 由用户给。
- [ ] 每个轴「越大越好 / 越小越好 / 越大越危险」？（**可推断+确认**）
- [ ] 轴之间是否等权？（**必问**：决定加权和 vs 乘积）

问法示例：

> 你提到动量、波动、估值三个指标。它们已经是 -1~1 的方向分，还是要我从原始值转换？
> 另外「估值」是越高越危险、越低越安全，对吗？

## 2. 状态（states）

- [ ] 状态集合与名称？（**可推断+确认**）
- [ ] 状态的**声明顺序**？（**必问**：决定 argmax 平局与 drift 键顺序）
- [ ] 每个状态的业务含义？（**必问**：用于解释与命名）
- [ ] 哪些状态属于多头侧 / 空头侧？（**必问**：只有做 `assert_monotone` 时才需要）
- [ ] 状态数是否 ≥ 2？（`Engine` 硬性要求）

问法示例：

> 状态顺序按「进攻 → 中性 → 防御」声明可以吗？平局时会取更靠前的状态。

## 3. 状态证据公式

- [ ] 「高/低/接近 0/尚未发生/明显为负」分别对应哪种算子？（见 `ops-selection.md`，**可推断+确认**）
- [ ] 多轴之间是「同时满足（乘）」还是「综合打分（加权和）」？（**必问**）
- [ ] 是否需要死区（轻微偏离不算）与饱和（超过某点不再增加）？（**必问**）
- [ ] 某个轴缺值时该状态证据给多少？（**必问**：`None→0` / `None→0.5` / 跳过该轴）

## 4. cap（每状态可达上限）

- [ ] 每个状态公式在输入域上的**最大值**是多少？（**推导+确认**，见 `ops-selection.md`）
- [ ] 若公式是乘积：各因子上界相乘是多少？
- [ ] 若公式是加权和：权重之和是否已归一？（未归一则 cap ≈ 权重和）

> cap 不是超参，而是结构常数；写错会让状态之间不可比。不要一律填 1.0。

## 5. 参数（Params）

- [ ] `temperature`：越小分布越尖锐。用户希望「明显信号」时 P_top 大约多高？（**必问或授权**）
- [ ] `uncertain_p_top`：P_top 低于多少标记不确定？取值 `(0, 1]`。（**必问或授权**）
- [ ] `trigger_threshold`：只有需要迁移归因（哪些轴触发了迁移）时才需，`>= 0`。（**可选**）

问法示例：

> 两个校准参数需要你定：
> 1) temperature 越小越「果断」；想要明显信号时 P_top≈0.8 就用小一点（如 0.2–0.5）。
> 2) uncertain_p_top 控制何时标记「不确定」，常见 0.5–0.7。
> 或者你授权我用建议值（会在交付物里标注为假设）。

## 6. 迁移图（可选）

- [ ] 状态之间是否允许直接跳转，还是只能逐级变化？（**必问，仅当用户提到流转**）
- [ ] 反向边是否合法？用 `TransitionGraph.chain(...)` / `.with_backward()` / `.add(...)`。
- [ ] 未给出迁移图时：`transition.kind` 对任何跨状态都将是 `illegal`，需在交付物中说明。

## 7. 输入与缺失

- [ ] 用户给的值是否可能缺失？（**必问**）
- [ ] 缺失时是否仍要出分布？（缺失轴按算子口径处理，不补 0；全缺时分布会接近均匀）
- [ ] 输入键名是否与 `factors` 完全一致？（大小写、拼写）

---

## 一个完整的问答示例

用户：

> 动量高、波动低是进攻；动量低、波动高是防御；其他是中性。

Agent 追问：

1. 三个轴是否已经是 `[-1,1]` 方向分？还是给原始量？
2. 「高/低」大概以多少为界？动量 >0.3 算高？（候选 0.2 / 0.3 / 0.5）
3. 中性的定义是「动量与波动都不极端」，还是「两边信号互相抵消」？
4. temperature 与 uncertain_p_top 你定，还是我用建议值（temperature=0.5、uncertain_p_top=0.6）？
5. 防御能否直接跳回进攻，还是必须经过中性？

用户回答后，落到规格摘要，再生成代码并校验。若用户授权默认，交付物中单列：

```
假设（用户授权采用）：
- temperature = 0.5
- uncertain_p_top = 0.6
- 中性态 = 动量与波动都落在 ±0.3 内（neutral_band）
- 迁移：进攻 ↔ 中性 ↔ 防御（允许双向）
```
