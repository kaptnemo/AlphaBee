# AlphaBee 混合智能路线图（确定性骨 × LLM 脑）

> 本文件是**横向治理路线图**，不替代 `ROADMAP.md`、`ENGINEERING_ROADMAP.md`、`MIDTERM_INVESTMENT_ROADMAP.md` 等专项文档；
> 它回答一个跨模块的问题：**在"确定性业务代码很多"的前提下，如何让系统持续符合 Agent 工程的发展方向。**
>
> 状态标记：✅ 已具备　🟡 部分具备　⬜ 未开始　⏸ 有条件暂停

---

## 一、背景判断（结论先行）

AlphaBee 目前是"**以确定性为骨、以 LLM 为脑**"的混合系统：数值计算、契约、状态机、风控与组合由代码完成；
事实理解、冲突探索、假设验证、洞察综合与报告由 LLM 完成。这个结构**符合生产级 Agent 的主流方向**，
不是"落后于智能体"。

真正的风险不在"确定性代码多"，而在三件事：

1. **未校准的常量被当成知识**：大量手调阈值（`0.2` / `0.3` / `20pp` / `15pp` / `0.22` / `0.55` …）缺少来源、版本与证伪机制。
2. **LLM 节点被装饰化**：LLM 产出的冲突/验证/洞察如果最终不进入决策，只是生成解释，系统实际退化为专家系统。
3. **规则熵**：派生/信号/勾稽/论点/中期多引擎的规则数量持续增长，交互与双重计数难以度量，规则"只增不减"。

因此本路线图的目标不是"减少确定性代码"，而是：

> **让确定性知识可校准、让 LLM 判断可进入决策、让规则体系可度量与演化。**

## 二、战略原则

| # | 原则 | 含义 | 反面 |
|---|---|---|---|
| P1 | 确定性是底座，不是过渡方案 | 数值、时点、契约、风控、合规、组合必须可复现可审计 | 把算账交给 LLM |
| P2 | LLM 提判断，代码做裁决 | LLM 负责开放/模糊/非结构化；代码负责度量与收口（LLM proposes, code disposes） | LLM 拍脑袋决定仓位 |
| P3 | 阈值即假设 | 每个常量都有来源、版本、回测或专家评审记录，可被数据推翻 | 手调后写死、永不复核 |
| P4 | 新规则必须证明增量价值 | 新规则要能说明它改变了哪些历史结论、改善了什么指标 | 只增不减的规则森林 |
| P5 | 自主性按需引入 | 用 workflow 解决确定问题，只在开放问题上引入 planner/reflection/多智能体 | 为"像 Agent"而端到端自主 |

## 三、自检基线（把 6 个问题变成可量化的体检项）

> 这些是全仓体检项，不绑定单个模块。每次里程碑评审时更新"当前值"。

| # | 自检问题 | 度量指标 | 数据来源 | 通过标准（建议） | 当前 |
|---|---|---|---|---|---|
| Q1 | 手调常量是否可溯源？ | 常量溯源率 = 有来源/版本/回测标注的常量数 ÷ 常量总数 | 代码常量区 + YAML + 配置 | ≥ 90%（P0 常量 100%） | ⬜ |
| Q2 | LLM 结论是否进入决策？ | LLM 结论消费率 = 被决策/评分/报告结构消费的 LLM 输出字段数 ÷ LLM 输出字段数 | 契约追踪（artifact → 消费者） | 100%，且"仅叙述"字段显式标注 | 🟡 |
| Q3 | 是否有校准语料？ | 真实帧数、带结果样本数、黄金帧数 | `data/midterm/state`、任务记录、回测集 | 真实帧 ≥ 50（沿用 V2/F-Marginal 既有门槛） | 🟡（历史登记仅 2 帧） |
| Q4 | 规则增量价值是否可测？ | 可消融规则占比、最近一次变更影响报告覆盖 | 规则注册表 + 消融脚本 | 新规则 100% 附增量报告 | ⬜ |
| Q5 | 变更影响是否可量化？ | 变更影响报告覆盖率（阈值/公式/权重改动） | CI/脚本产出 | 行为变更 100% 附影响报告 | 🟡 |
| Q6 | 规则/LLM 边界是否错配？ | 错配清单条目数（规则硬编码了判断 / LLM 做了算术） | 边界审计 | 0 个 P0 错配；P1 有整改计划 | ⬜ |

## 四、战略方向 → 工作流（W1–W5）

### W1：常量与阈值治理（P0）

**目标**：把"专家直觉编码"升级为"可追溯、可版本化、可证伪的知识资产"。

**范围**：
- `alphabee/midterm/score_engine.py` 全部参数常量（beat/miss/ocf/segment/marginal）。
- `alphabee/midterm/classifier_v2.py`（`TEMPERATURE` / `UNCERTAIN_P_TOP` / `BREAK_LAMBDA` / `S0_FLOOR`）。
- `alphabee/agents/derived_facts/rules/*.yaml`、`signal/rules/*.yaml`、`anomaly` 规则阈值。
- `config.yaml` 中带默认值的业务阈值。

**交付物**：
1. **常量登记表**（本文件附录 A 为首版）：每个常量记录 `值 / 语义 / 来源 / 版本 / 复核条件 / 回滚方式`。
2. **来源分级**：`backtest`（回测）/ `expert`（专家评审）/ `literature`（文献/框架）/ `placeholder`（待校准）。
3. **待校准清单**：所有 `placeholder` 进入 W2 的校准队列，禁止静默转为"确定值"。

**验收**：
- Q1 ≥ 90%，P0 常量 100% 有来源标注。
- 新增/修改常量若未登记，CI 或评审直接阻断（沿用现有"行为变更登记"纪律）。

**非目标**：不追求一次把所有阈值调到最优；本工作流只解决"可追溯与可校准"。

---

### W2：校准与回测闭环（P0）

**目标**：让阈值和权重能被真实数据检验，而不是永久冻结。

**范围与现有资产复用**：
- 已有 `scripts/calibrate_tracking_thresholds.py`（离线回放告警 JSONL）、`scripts/f_marginal_shadow.py` + `alphabee/midterm/marginal_shadow.py`（影子统计）。
- 已有 V2 设计 §7.3 的校准规程与"真实帧 ≥ 50 才可复核"门槛。
- 已有 F-Marginal G-8 五项门槛（|ΔF|、翻转率、危险翻转、覆盖率）。

**交付物**：
1. **黄金帧集（Golden Frames）**：固定一批真实帧 + 期望状态/分布，作为回归与校准基线。
2. **消融/回放协议**：对单个阈值/规则做 on/off 回放，输出影响报告（结论变化率、状态迁移率、EV/仓位变化）。
3. **结果反馈层**：把"事后表现"（状态命中、超额收益、回撤）与当时的因子/证据对齐，形成校准样本。
4. **校准决策记录**：每次参数变更写明"旧值→新值、样本量、指标变化、是否达标、回滚条件"。

**验收**：
- 真实帧 ≥ 50 后，完成至少一轮 `TEMPERATURE` / `UNCERTAIN_P_TOP` / `F_MARGINAL_WEIGHT` 的复核（可保留原值，但必须有记录）。
- 任一 P0 阈值变更都能产出影响报告。
- Q3、Q5 达标。

**非目标**：不在语料不足时用"小样本调参"制造虚假精度；语料不足时只做形状约束并显式标注。

---

### W3：LLM 判断闭环（P0/P1）

**目标**：确保 LLM 的冲突探索、假设验证、洞察综合**真正影响决策**，同时避免其不确定性污染数值链路。

**交付物**：
1. **判断权威矩阵（Authority Matrix）**：逐结论类型声明"谁有最终裁决权"：

   | 结论类型 | 数值/规则权威 | LLM 权威 | 仲裁规则 |
   |---|---|---|---|
   | 财务数值、比率、时点 | ✅ | ❌ | 以 canonical 事实为准 |
   | 异常/信号触发 | ✅ | ❌ | 规则阈值 + 证据回链 |
   | 冲突是否存在 | 🟡 | ✅ | LLM 生成、验证层结算 |
   | 假设成立/证伪 | 🟡 | ✅ | 唯证据论 + 置信度 |
   | 中心观点/叙述 | ❌ | ✅ | 以已结算证据为边界 |
   | 仓位/风控 | ✅ | ❌ | 代码裁决，LLM 不得越权 |

2. **结构化输出与消费追踪**：LLM 输出必须可解析、可校验；每个字段标注下游消费者（无消费者则视为"仅叙述"并显式登记）。
3. **贡献度度量**：对 LLM 节点做"开/关"对比（同一批帧），量化其对状态、结论、报告质量的影响；长期目标是把"装饰性输出"降为 0。
4. **不确定性表达**：延续 `uncertain` / `entropy_normalized` / `degraded` / `missing_facts` 的显式化，禁止把 softmax 权重表述为概率。

**验收**：
- Q2 达标（LLM 输出 100% 有消费路径或显式"仅叙述"标注）。
- 至少完成一次 LLM 节点开/关贡献度报告。
- 权威矩阵在核心契约文档中可见。

**非目标**：不让 LLM 接管数值计算、仓位与合规判断。

---

### W4：规则熵治理（P1）

**目标**：让规则体系可注册、可退役、可正交化，避免"只增不减"。

**交付物**：
1. **规则注册表**：派生/信号/勾稽/论点/中期规则统一登记 `id / 维度 / 依赖 / 状态（proposal/active/deprecated）/ 引入原因 / 增量证据`。
2. **生命周期**：新规则需附"增量价值报告"才能从 `proposal` 升 `active`；长期无增量或与其他规则高度重叠的规则进入 `deprecated`。
3. **正交化/去重**：识别双重计数与高相关规则（如 beat 与边际加速的既有去重逻辑，应作为范式推广）。
4. **规则覆盖率与冲突审计**：定期输出"同帧多规则方向冲突"清单，评估是否需要仲裁。

**验收**：
- 规则注册表覆盖 100% `active` 规则。
- 最近一个季度新增规则 100% 附增量报告。
- 产出一份"规则重叠/双重计数"审计报告。

---

### W5：评测、可观测性与变更影响（P1）

**目标**：把"能不能跑"升级为"能不能度量、回归、定位失败"。

**交付物**：
1. **评测分层**：单元（现有 3141 项）→ 契约（artifact 传播）→ 帧级（黄金帧）→ 结果级（事后表现）。
2. **变更影响报告**：阈值/公式/权重/LLM prompt 改动时，自动对比黄金帧的结论变化。
3. **失败分类学**：数据缺失 / 规则不可达 / LLM 解析失败 / 证据不足 / 语境错配，分别统计与告警。
4. **可观测面板**：状态分布、`uncertain` 比例、缺失率、LLM 降级率、规则命中率、成本/时延。

**验收**：
- 行为变更 100% 附影响报告（Q5）。
- 失败分类可在一次 run 的产物中定位到具体层级。

---

### W6（有条件）：有限自主能力演进（P2 / ⏸）

**目标**：只在开放问题上引入 agentic 模式，且必须有明确收益与护栏。

**候选方向**（按价值/风险排序）：
1. **Planner**：在"验证假设"阶段动态决定查什么，而不是固定工具序列（已有工具丰富，收益较高）。
2. **Reflection**：报告/论点生成后的自我反驳与重写（已有 `review_report`，可增强）。
3. **Memory**：跨 run 的证据/论点/画像版本化（已有 thesis 版本、帧持久化，可扩展）。
4. **多智能体辩论**：仅在结论分歧高、且可证伪的场景引入，需成本护栏。
5. **Human-in-the-loop**：高风险决策的人工确认点（已有 `require_human_confirm` 纪律）。

**准入条件**：W1–W5 的度量闭环先达标；否则自主性只会放大不可观测的偏差。

## 六、度量面板（建议 North Star 与护栏）

**North Star（择一或组合）**
- 决策可解释率：结论能追溯到"证据 → 规则/LLM 判断 → 决策"的链路比例。
- 校准质量：状态/评分的命中率与校准曲线（需 W2 结果反馈层）。

**Leading indicators**
- 常量溯源率、规则增量报告覆盖率、LLM 消费率、黄金帧通过率。

**Guardrails（不得恶化）**
- 可复现性（同输入同输出）、审计完整性、成本/时延、规则总数与重叠度。

## 七、非目标与反模式

**非目标**
- 不把数值计算、时点对齐、风控、合规、组合约束交给 LLM。
- 不追求端到端全自主 agent。
- 不为"智能体化"而重写已验证的确定性链路。
- 不在语料不足时宣称校准完成。

**反模式（出现即纠正）**
- 新增无来源阈值，或把 `placeholder` 静默当确定值。
- LLM 输出只进报告叙述、不进任何决策/结构字段，却未标注"仅叙述"。
- 规则只增不减，没有增量价值证明与退役机制。
- 把 softmax 模式权重表述为"概率/后验"。
- 用规则硬编码本应由 LLM 判断的语义取舍（或反之）。
- 用小样本调参制造"精确"假象。

## 八、行为变更与登记纪律（沿用现有）

1. 任何阈值/权重/公式/LLM prompt 的默认值变更，必须在对应专项 Roadmap 的"行为变更登记"表登记：`旧值 / 新值 / 依据 / 影响面 / 回滚方式`。
2. 设计有要求但未落地的点，进入"顺延项登记"，写明"当前不可达的依据 + 收口条件"，不得静默略过。
3. 校准类变更必须同时给出样本量、指标变化与是否达标；未达标只能保留原值并标注"待复核"。
4. 新规则必须有"变异/消融可杀死"的证据，禁止不可观测的等价变异体计入价值。

## 九、开放问题（需 owner 裁定）

1. **阈值来源标准**：`expert` 评审是否足够，还是必须回测？不同风险级别是否采用不同标准？
2. **结果定义**：校准的 ground truth 用什么——状态命中、相对超额收益、回撤、还是人工标注？
3. **权威矩阵的最终形态**：冲突/假设的最终裁决是 LLM + 验证层，还是完全规则化？边界如何随证据强度变化？
4. **语料获取**：真实帧 ≥ 50 的达标路径与隐私/合规边界。
5. **自主性上限**：哪些决策永远不允许 LLM 单独裁决（仓位/止损/合规）？
