## 0. 一页速览

**这个模式的一句话**：状态不是「总分落在哪个区间」，而是「N 个语义模式里，哪一个被证据支持得最多」；
证据由**门控 × 支撑 × 否决**三件事写成，除以「该状态可达上限」变成可比量，再 softmax 成**软状态分布**；
分布只用来做三件事——`argmax` 定**动作类型**、分布期望定**动作力度**、阈值与赔率定**门槛**。

五层管线（每一层都是确定性纯函数）：

| 层 | 输入 | 输出 | 一句话职责 | 本仓落点 |
|---|---|---|---|---|
| L0 原始 | 外部数据 / canonical 字段 | 多期数值 | 只搬运，不做判断 | adapter / `factors.py` |
| L1 方向分 | 原始值（多量纲） | `[-1,1]` 方向分（缺失 `None`） | 把不同量纲压成**同一符号语义**（正 = 对结论有利） | `score_engine.py` |
| L2 模式证据 | 方向分 | 每状态一个非负证据 | **按模式打分，不跨状态求和** | `classifier_v2.py::state_evidence` |
| L3 分布 | 证据 | 归一化证据 + 概率单纯形 | 除上限 → softmax → 软状态 | `normalized_evidence` / `distribution` |
| L4 决策 | 分布 + 后验 + 赔率 | 动作 / 仓位 / 研究任务 | 类型、力度、门槛三轴解耦 | `position.py` / `decision_model.py` |

**三条铁律**（违反任何一条，模型会在某个边界上静默错掉）：

1. **不跨状态求和定状态**：状态之间是「模式竞争」，不是「打分累计」；只要允许 `Σ w_i·x_i`，就会出现
   「估值便宜 0.6 抵消基本面崩盘」的补偿错误（设计文档 §1）。
2. **缺失不得静默回 0**：缺失要么显式 `None`（不参与），要么给「信息不足」的中性值（0.5），
   绝不能让缺失伪装成「中性证据」或「无证据」。
3. **状态间上限必须可比**：softmax 前不归一化，等于把「不同状态的公式量纲差」偷偷变成**状态先验**。

**算子组合的一句话**：`方向分 → 门控×支撑×否决 → ÷可达上限 → softmax/T → argmax/期望/阈值`。

## 1. 适用范围与替代方案

### 1.1 什么时候该用这个模式

同时满足以下 4 条时，模式收益最大：

1. **状态是语义相位**，不是数值本身：研报里的「预期差形成 / 证据确认 / 共识扩散 / 充分定价 / 退出」、
   订单生命周期、服务健康度、信用迁徙、告警等级……人话能说清「这个状态意味着什么动作」。
2. **信号是多轴且方向可解释**：每个轴能独立回答「对结论是更有利还是更不利」，符号有业务含义。
3. **矛盾态是常态**：多轴经常不同向（业绩好但股价不涨），不能用一个总分抹平。
4. **必须可审计**：要能回答「为什么判成 S2」，且同一输入必须复现同一结论（回测、合规、复盘）。

### 1.2 四种做法的失败模式对比

| 做法 | 形状 | 典型失败模式 |
|---|---|---|
| **A. 加权总分 + 阈值分档** | `score = Σ w_i·x_i`，`if score > 0.6: 状态=X` | 补偿错误（便宜抵消崩盘）；阈值附近抖动；状态间无迁移语义；无法表达「模式」 |
| **B. 硬规则 if-else** | `if F>0.3 and E>0.3: S3` | 边界跳变、无软状态、矛盾帧无出口、规则组合爆炸、不可回测 |
| **C. 监督学习分类器** | 特征 → softmax | 样本需求、漂移、不可审计、标签本身难定义；适合「有大量标注」而非「语义建模」 |
| **D. 本模式：模式证据 + 软状态** | 门控×支撑×否决 → 归一 → softmax | 需要设计者显式写出模式与上限；参数需校准；好处是每一步都可读、可测、可回滚 |

### 1.3 不该用的场景

- 目标本质是**回归/排序**（预测收益率、排雷排序）——直接用连续模型，别把信息压成 6 档再展开。
- 状态边界由**外部标签**定义（交易所行业分类、评级机构等级）——照抄定义，别自创。
- 轴没有稳定符号语义（例如「新闻情绪」本身方向不明）——先解决语义判读（见 `SEMANTIC_JUDGMENT_CONTRACT_DESIGN.md`），再谈状态。

## 2. 分层架构与契约边界

```text
外部字段 ──adapter──▶ canonical 字段（原始值，None = 缺失）
                          │
                          ▼
                 L1 方向分 [-1,1]（每轴独立，不跨轴求和）
                          │
                          ▼
                 L2 模式证据（每状态一个数；门控×支撑×否决）
                          │  ÷ 每状态可达上限 cap
                          ▼
                 L3 归一化证据 [0,1] ──softmax(logit/T)──▶ 软状态分布 P
                          │                                   │
                          │                                   ├─ argmax → 动作类型锚点
                          │                                   ├─ Σ P·band → 动作力度
                          │                                   └─ 熵 / P_top → 不确定性与研究任务
                          ▼
                 L4 后验置信 / 情景概率 / EV / 仓位（类型 × 力度 × 门槛）
```

**边界纪律（本仓已验证的四条）**：

| 边界 | 规则 | 违反后的症状 |
|---|---|---|
| L1 内部 | 每个方向分**独立**产出，禁止跨因子加权求和 | 一个极端因子被另一个抵消，模式失效 |
| L1 → L2 | L1 只输出分，不输出状态；L2 只读分，不回写原始值 | 「决策算一份、报告再算一份」双份真相 |
| L2 → L3 | 公式与归一化分离，公式里不出现 `÷cap` | 改温度/改上限时要动公式，回测不可复现 |
| L3 → L4 | 状态只提供**动作类型**，不直接决定仓位大小 | `if state == "S2": buy()` 反模式（§7） |

**单一来源**：下游只消费上游**已算好**的中间量，不重算。例：`classifier_v2.classify_state` 把
`state_evidence`（归一化证据）透出到 `ClassifierResult`，`decision_model.evaluate` 原样写进
`CompanyStateArtifact`；报告 / CLI / 任务记录都读 artifact，不重新跑 softmax。

## 3. 模式的形式化

### 3.1 记号

- 轴（因子）集合 `A = {F, E, T, V, C, R}`，每轴方向分 `x_a ∈ [-1,1] ∪ {None}`，正 = 对结论有利。
- 状态集合 `S = {S0…S5}`；证据 `E_s ≥ 0`；上限 `cap_s > 0`；归一化证据 `n_s ∈ [0,1]`；
  分布 `P_s > 0`，`Σ P_s = 1`；温度 `τ > 0`（代码常量 `TEMPERATURE`，本文用 `τ` 避免与趋势轴 `T` 混淆）；
  状态数 `K = 6`。
- 迁移图 `G = (S, legal_edges)`，`kind ∈ {stay, forward, downgrade, reopen, illegal}`。

### 3.2 四步公式（本仓 v2 的具体值）

```python
# ① 方向分（L1，score_engine.py）：符号统一后压到 [-1,1]，缺失 → None
# ② 模式证据（L2，classifier_v2.state_evidence）
S0 = S0_BASELINE * (S0_FLOOR + (1 - S0_FLOOR) * nf * ne * nt)
S1 = ne * (f_up + 0.5 * t_dn + 0.5 * v_up) * (1 - sf)
S2 = t_up * (f_up + ne)                 # order="tef"：价格先确认
S2 = e_up * (f_up + nt)                 # order="etf"：预期先确认
S3 = 3 * min(f_up, e_up, t_up)          # 三共振：木桶短板
S4 = t_dn * (not_yet(e) + v_dn + c_dn)  # order="tef"：价格破位先导
S4 = not_yet(e) * (t_dn + v_dn + c_dn)  # order="etf"：预期停上修先导
S5 = max(t_dn * (e_dn + 0.5 * f_dn),        # 路径 A：价格破位确认
         BREAK_LAMBDA * se * sf)            # 路径 B：F×E 双击证伪（价格不破位也可达）

# ③ 归一化 + 分布（L3）
n_s = clip01(E_s / cap_s)                       # 每状态先可达 1.0，才谈得上比较
P_s = softmax(n_s / TEMPERATURE)                # 均匀先验 = 在 logit 上加常数，可省
H   = -Σ P_s·ln P_s        ;  H_norm = H / ln(6)      # 分布离散度，∈[0,1]
P_top = max(P_s)                                # 「状态确信度」，不是概率

# ④ 决策（L4）
动作类型 = ARGMAX_MAP[argmax(P)]                 # 只做粗粒度意图锚点
动作力度 = Σ P_s · weight_band_midpoint[s]       # 软状态期望：熵高 ⇒ 力度自动保守
门槛     = f(后验 confidence, RiskAdjustedEV)    # 赔率不足 → 打折或压 0
```

### 3.3 「门控 × 支撑 × 否决」语法（最值得抄走的一条）

把每个状态的证据写成三件事的乘积，语义最清楚、也最不容易出符号错误：

```text
E_s = G_s(轴上的"是不是这个模式") × [ Σ w_i · S_i(同向支撑强度) ] × V_s(否决项)
```

- **G（gate，门控）**：`∈ [0,1]`，负责回答「现在是不是这个模式的时机」。门控通常放在**领先轴**上
  （`tef` 用 `t_up` / `t_dn`，`etf` 用 `e_up` / `not_yet(e)`）。
- **S（support，支撑）**：同一模式内部的强度**相加**（`f_up + 0.5·t_dn + 0.5·v_up`）。
  系数 1.0 = 主证据，0.5 = 伴随证据；**只在同一状态内部求和**，绝不跨状态。
- **V（veto，否决）**：`∈ [0,1]`，乘上去把「看起来像但语义不对」的帧压掉。
  例：`S1 × (1 - sf)` —— F 已实质恶化时，「便宜 + 价格弱」不能叫预期差。

逐状态拆解（评审时直接照这张表问「门的物理含义是什么」）：

| 状态 | G 门控 | S 支撑（括号内） | V 否决 | cap |
|---|---|---|---|---|
| S0 研究候选 | 恒 1（底噪基线） | `nf·ne·nt`：三轴**同时**接近中性（乘积 = AND） | — | 0.30 |
| S1 预期差形成 | `ne`：预期尚未上修 | `f_up + 0.5·t_dn + 0.5·v_up` | `1 - sf`：F 实质恶化不算预期差 | 2.0 |
| S2 证据确认 | `t_up`（tef）/ `e_up`（etf） | `f_up + ne` / `f_up + nt` | — | 2.0 |
| S3 共识扩散 | 无（`min` 自带门控） | `3·min(f_up,e_up,t_up)`：木桶 | — | 3.0 |
| S4 充分定价 | `t_dn`（tef）/ `not_yet(e)`（etf） | `+ v_dn + c_dn`（+ `not_yet` / `t_dn`） | — | 3.0 |
| S5 退出-A 价格路径 | `t_dn`：破位确认 | `e_dn + 0.5·f_dn` | — | 1.5 |
| S5 退出-B 证伪路径 | `se·sf`：F、E **同时**实质恶化 | `× BREAK_LAMBDA` | `SEVERE_LO` 死区防「轻微下修」 | 2.0 |

> **S0 的形式偏差**：S0 是唯一不完全符合 `G×S×V` 的状态——它的底噪是**加性**的
> （`BASELINE × (FLOOR + (1-FLOOR)·neutrality)`），可视为 `G=1`、`S=该式`。加性底噪会带来
> 「恒定比较优势」，量级必须小（见 D5）。

三个可直接复用的判断：

1. **乘积 = AND，加法 = OR/补偿，`min` = 软 AND（带幅度），`max` = 多路径 OR（不重复计数）**。
   `nf·ne·nt`（S0）是「三轴都得接近中性」；`min`（S3）是「最弱一环决定共识强度」；`max`（S5）是
   「价格破位 **或** 双击证伪」，用 `max` 而不是加法，避免两条路径同时满足时被重复放大。
2. **门控只放在领先轴上，是「顺序哲学」的唯一落点**。`etf` / `tef` 两个变体的 `S0/S1/S3` **逐值相等**，
   v2 的 `S5` 也已与顺序解耦（两条路径取 `max`，证伪通路不含 `T`），差异只剩 `S2/S4` 的门控落点——
   这一条由测试钉住（`test_etf_and_tef_share_non_gated_states`），所以「顺序」是**一个显式参数**，
   不是散落在公式里的隐式假设。**注意 v1 时代顺序还改动过 `S5`**（`classifier_tef` 的 S5 被 `t_dn`
   门控，`T ≥ 0` 即恒 0），v2 把这个耦合显式拆掉了——这正是 D2 的修法。
3. **支撑项与否决项必须分轴**：`S1` 里 F 的**正向**贡献在支撑（`f_up`），F 的**负向**后果在否决（`1-sf`），
   同一轴不在同一处正负相抵——否则模型会自己把自己抹平。

### 3.4 状态族设计：入口 / 过程 / 出口 + 底噪

可复用的状态族骨架：

- **入口态**（S0）：吸收「无信号 / 信号互相矛盾」两种情形。它必须**带底噪**，否则当所有轴都接近 0 时
  会出现「全零证据 → softmax 均分 1/6」的假高熵（`test_i9_no_zero_evidence_uniform`）；
- **过程态**（S1–S4）：按生命周期排序，每个状态对应一种**动作类型**（试探 / 加仓 / 核心 / 减仓）；
- **出口态**（S5）：至少要有**两条互相独立的到达路径**（价格路径 + 基本面路径），否则「退出」会在某个
  半空间上数学不可达（§7 的 D2 就是这个病）。

**底噪的正确量级**：归一化后 `n(S0) = floor + (1-floor)·neutrality ≥ floor`，即底噪是**与输入无关的恒定
比较优势**。`floor=0.30` 时 S0 在任何帧上都至少拿 0.30 的归一化证据，会压过大量 0.24–0.28 的正常状态
（本仓实测：S0 占 argmax 55.5%，其中明确偏多帧仍占 29.0%）；`floor=0.10` 才既保留「矛盾 ⇒ 研究候选」
语义，又不抢正常信号帧。**结论：底噪要小，小到只吸收「什么都说不清」的帧。**

### 3.5 语义声明：像概率的量必须声明它是什么

本仓有两个都落在 `[0,1]`、都叫「概率味道」的量，**语义完全不同，绝不可混用**：

| 量 | 数学身份 | 用途 | 禁止用法 |
|---|---|---|---|
| `P`（softmax 输出） | 「归一化模式证据的 softmax 权重」，**不是频率概率**，**不是 P(H\|E) 后验** | `argmax` / 期望力度 / `P_top` 判不确定性 | 当置信区间、当胜率、直接乘收益当 EV |
| `confidence`（log-odds 后验） | P(H\|E)，贝叶斯后验 | 缩放仓位力度、情景概率 | 与 `P_top` 相加/相乘比较 |

配套动作：结果对象里带 `probability_source ∈ {bayes_posterior, state_prior}`，报告文案里显式写
「P 是模式权重，不是概率」。**命名可以沿用旧习惯（如「状态确信度」），但语义声明必须进 docstring 与报告。**
`H_norm = H/ln(K)` 同理——它只是分布离散度，不是「不确定性概率」。

### 3.6 顺序哲学作为参数（2×2 正交）

不要为「顺序不同」复制两套实现；把它做成**一个参数 + 一张矩阵**：

| | `etf`（E→T→F） | `tef`（T→E→F） |
|---|---|---|
| **formula=v1** | `classifier.py`（冻结） | `classifier_tef.py`（冻结） |
| **formula=v2** | `classifier_v2.py(order="etf")` | `classifier_v2.py(order="tef")` |

正交化的好处：v1/v2 的差异（公式）与 etf/tef 的差异（门控落点）可以**分别归因**，A/B 实验不会互相污染。
参数校验要点：非法值 **raise `ValueError`**（公式内部严肃校验），配置解析层 **fail-open**（读配置异常
绝不打断主流程）——两层口径不同是刻意的，别把两者写成同一个兜底。

### 4.1 值域 / 缩放族

```python
clip01(x)            = max(0, min(1, x))
saturate(v, scale)   = clip(v/scale, -1, 1)                  # 正负对称
log1p_saturate(v, r) = sign(v) · min(1, log1p(|v|) / r)      # r = log1p(ref)
```

**要解决的问题**：不同量纲（百分比、元、排名、分位）必须压到同一符号域，否则「谁的绝对值大谁说话」。

**`saturate` vs `log1p_saturate` 的选择**：

- 线性饱和：适合「超过某个业务阈值就没有额外信息」的量（YoY 超过 30% 就不再加分）；
- `log1p` 反饱和：适合「幅度差异本身有意义、但需要压缩长尾」的量。本仓 E 轴用 `ref=100%`：
  上修 100% → ±1、45% → ≈0.83、5% → ≈0.39。若用线性 `saturate(x, 100)`，45% 与 100% 的差别会被
  压成 0.45 vs 1.0，实际效果是「大幅上修」永远拿不到接近满分。

**scale 的取法**（本仓经验，均为「结构性示意、应回测」）：

| scale | 值 | 业务含义（=「一单位饱和点」） |
|---|---|---|
| `_FUNDAMENTAL_YOY_SCALE` | 30 | 营收/净利 YoY 30% 已是高质量成长 |
| `_REVISION_REF` | 100 | 分析师上修 100% 封顶，45% 仍保留 ≈0.83 |
| `_RS_SCALE` | 20 | 20% 超额收益已是强相对强度 |
| `_MARGIN_DELTA_SCALE` | 4 | 毛利率同比 −4pp 已是实质恶化 |
| `_PLEDGE_SCALE` | 50 | 质押率 50% 视为满分风险 |
| `_GOODWILL_SCALE` | 1e9 | 商誉 10 亿视为满分风险 |

**规则**：scale 必须能写成一句业务话（「XX 到这个量级就算极端」）。写不出这句话，说明这个 scale
是拍脑袋的，先去做分布统计。

### 4.2 符号 / 方向族

```python
up(x) = clip01(x)        # 正部
dn(x) = clip01(-x)       # 负部
```

**约定：所有轴统一「正 = 对结论有利」**（本仓：F 边际改善为正、E 上修为正、V 便宜为正、C 不拥挤为正、
R 风险下降为正）。统一符号的价值在于：公式里所有 `*_up` / `*_dn` 都可以互换复用，评审时不必逐项反推
「这个 0.6 是看多还是看空」。

**缺失 → 0**，而不是 0.5：`up/dn` 表达的是「有没有强度」，缺失就是没有强度，
给 0.5 会凭空造出一份强度证据。至于「缺失应该打多少折扣」是 `neutral_band` / `not_yet` 的职责，
不要在这里混进来。

### 4.3 接近度 / 距离族（本仓三个核心算子）

```python
neutral_band(x, w) = clip01(1 - |x| / w)         # 双侧：|x|≥w → 0；x=0 → 1；缺失 → 0.5
not_yet(x, w)      = 1 - max(0, x) / w           # 单侧：x≤0 → 1；x≥w → 0（可为负）；缺失 → 0.5
severe(x, lo, hi)  = 0 if x ≥ 0 or |x| ≤ lo else 1 if |x| ≥ hi
                     else (|x| - lo) / (hi - lo) # 仅负侧；缺失 → 0
```

三者的分工是本模式最容易搞混、也最容易出错的地方：

| 想表达 | 用哪个 | 语义 | 缺失口径 |
|---|---|---|---|
| 「这个轴**接近中性/尚未成形**」（两侧都不该加分） | `neutral_band` | 钟形，双侧衰减 | 0.5（信息不足给半分信用） |
| 「这个轴**还没有发生/尚未上修**」（只看正侧） | `not_yet` | 单调不增；`x > w` 时出负值 = 反证据 | 0.5 |
| 「这个轴**恶化到什么程度**」（只看负侧，且带死区） | `severe` | 死区（abs(x) ≤ lo 不惩罚）+ 线性 + 饱和 | 0（不制造证伪） |

**最关键的判据：门控项是「双侧」还是「单侧」，由语义决定，不能照抄。**

- 「预期尚未上修」用 `not_yet`：E 转负**完全满足**「停上修」，所以 S4 用单侧是对的；
- 「预期/价格**尚未共振、尚未确认**」必须用 `neutral_band`：如果也用单侧，该轴**越负、对应多头状态的
  证据反而越高**（v1 的 S1 门控 `not_up(e)`、v1-tef 的 S2 伴随项 `not_up(e)`、v1-etf 的 S2 伴随项
  `not_up(t)` 都是这个病灶）——这就是本仓 v1 的 **D1 符号方向错误**（「恶化 = 确认」），
  属于语义反转，**调参永远修不好**。

**`not_yet` 允许出负值**是一个刻意的设计：`E` 强上修时「预期停上修」应该给**负证据**，而不是 0。
负值由归一化入口统一的 `clip01` 吸收（反证据 = 0），因此**值域收敛只在这两处之一做**，不要算子内部
和归一化入口各 clip 一次且口径不一致。当前实现是「`neutral_band` 内部 clip、`not_yet` 交给归一化层收口」，
这种混合可以接受，但必须（a）写进 docstring，（b）由测试钉住边界行为（`test_operator_missing_value_semantics`）。

**`severe` 的死区**：`|x| ≤ SEVERE_LO(0.25)` 不计证伪，避免把「单季轻微负增长」判成顶背离；
`SEVERE_LO(0.25)` / `SEVERE_HI(0.60)` 构成「死区 + 线性 + 饱和」三段——这是所有「严重度」类算子的通用形状。

### 4.4 门控 / 聚合族

| 算子 | 数学 | 语义 | 什么时候用 | 坑 |
|---|---|---|---|---|
| 乘积 | `G·S·V` | AND（严格） | 门控、否决 | 门在 0 附近会把所有信号抹平；乘法顺序不影响结果但影响可读性 |
| `min` | `min(x₁…xₙ)` | 软 AND（带幅度） | 多轴共振，强度由最弱一环决定 | 轴一多会系统性偏低；适合 2–4 个轴 |
| `max` | `max(p₁…pₘ)` | 多路径 OR | 同一状态有多条独立到达路径 | 不能用加法替代（会双重计数） |
| 加权和 | `Σ wᵢ·Sᵢ` | OR / 补偿（仅在**同状态内部**） | 同一模式的多条伴随证据 | 跨状态求和 = 补偿错误（§1.2 A） |
| 缺失感知均值 | `mean(可用项)` | 平均（缺失不补 0） | 多源同质指标合成 | 补 0 会把中性当证据、系统性稀释 |
| 质量门 | `M = M_raw · Q` | 乘性折扣（下限不为 0） | 「量」要经过「质地」折价 | 下限归零会把「有瑕但有信息」直接抹成 0 |
| 单侧承载 | `a if b is None else b if a is None else w·a+(1-w)·b` | 缺一侧时另一侧全额承载 | 双锚点合成（预告 + 研报修正） | 缺一侧时**不要**按 0.6/0.4 缩放，否则等于「缺数据就扣分」 |

本仓 `_revision` 的写法可直接复用：两侧都有 → `0.6·anchor + 0.4·research`；只有一侧 → 该侧**全额承载**
（不缩放）；两侧全缺 → `None`。理由是「缺失是数据问题，不是质量判断」。

### 4.5 归一化 / 分布族

```python
n_s = clip01(E_s / cap_s)                  # ① 每状态除以其「可达上限」
logit_s = n_s / τ                          # ② 温度缩放（τ = TEMPERATURE）
P_s = exp(logit_s - max(logit)) / Σ exp(…) # ③ 数值稳定 softmax（减 max 不改结果）
H = -Σ P ln P ;  H_norm = H / ln(K)        # ④ 离散度（可跨状态/跨帧比较）
```

**`cap` 不是超参，是公式的结构常数**：`cap_s` = 该状态公式在输入域上的**可达最大值**。本仓的推导方式是
「门控上限 1 × 支撑系数之和」并用 witness 帧验证：

| 状态 | 推导 | cap | witness 帧（F,E,T,V,C） |
|---|---|---|---|
| S0 | `S0_BASELINE × 1.0`（neutrality=1） | 0.30 | `(0,0,0,0,0)` |
| S1 | `1 × (1+0.5+0.5) × 1` | 2.0 | `(1,0,-1,1,0)` |
| S2 | `1 × (1+1)` | 2.0 | `tef:(1,0,1,0,0)` / `etf:(1,1,0,0,0)` |
| S3 | `3 × min(1,1,1)` | 3.0 | `(1,1,1,-1,1)` |
| S4 | `1 × (1+1+1)` | 3.0 | `(0,0,-1,-1,-1)` |
| S5 | `max(1.5, BREAK_LAMBDA)` | `max(1.5,λ)` | `(-1,-1,1,0,0)` |

**三条必须用测试钉住的规则**：

1. **可达**：每个状态都存在输入使其归一化 = 1.0（否则该状态永远拿不到满证据，等于被隐式降权）；
2. **不越界**：网格上任何输入的证据 ≤ cap（否则 cap 不是上限，归一化会溢出被 clip）；
3. **耦合关系同步**：`EVIDENCE_CAPS["S5"] == max(1.5, BREAK_LAMBDA)` 在**导入期** `assert`
   ——改了 λ 忘记改 cap，S5 会被静默压到 <1，「每状态可达 1.0」不变量当场破掉。

**温度 τ 的作用与标定**：τ 越小分布越尖（argmax 越武断），τ 越大越平（所有帧都 uncertain）。
τ **不能用「看图调参」定**，要用聚合门（见 §5.1 的 I5）：对称性（完美多空 `P_top` 差 ≤0.10）、
判别性（无信号帧 `P(S0) ≥ 0.85`）、离散度合理（`H_norm` 中位数在合理区间）。

**softmax 的两个隐式陷阱**：

- **均匀先验 = logit 加常数**：省掉先验不是「没有先验」，而是「均匀先验」；要非均匀先验就显式加。
- **未归一化的量纲差 = 隐式状态先验**：`cap` 不齐时（v1：S3=3.0 / S5=1.5 / S0=0.30），softmax 会自动
  偏向大 cap 状态——这是 D3 的病根。反过来，`cap` 归一化也会**放大 cap 小的状态**（本仓实测：某帧 S0 原始
  证据 0.106，仅为 S2 的 1/5，归一化后 0.354 > S2 的 0.282），所以 cap 必须是**真实可达上限**，不能为了
  「看起来平衡」拍一个值。

### 4.6 置信 / 证据更新族（贝叶斯分支）

当输入是「离散证据事件」而不是「连续因子」时，本仓用 log-odds 而不是 softmax：

```python
logit(p)      = ln(p / (1-p))                       # 夹紧到 (1e-9, 1-1e-9)
sigmoid(x)    = 1 / (1 + e^-x)                      # 分段实现，防溢出
LR(d, effect)= (1+d)/(1-d)        if confirming
                (1-d)/(1+d)       if refuting       # d = 证据强度 ∈ [0,1)
                1                 if neutral
posterior    = clamp(sigmoid(logit(prior) + Σ w·ln LR), 0.05, 0.95)
```

可复用的四个技巧：

1. **强度 → 似然比**：`d` 用「强度」而不是「方向」；方向由 `effect` 决定，避免符号错误。
2. **不对称加权**：`refuting` 乘 1.2——反证比佐证更有信息量，否则多条 confirming 会轻易压倒少量 refuting。
3. **后验夹紧**：`[0.05, 0.95]`——没有证据能让人 100% 确信一个未被证实的假设。
4. **零证据显式降级**：无证据时返回 `prior`（可能为 `None`），**绝不静默假设 0.5**；并且给
   `probability_source="state_prior"` 标签，下游据此决定「保守收缩」（本仓把状态先验向均匀 1/3
   收缩一半：S3 bull 0.55 → 0.44），避免「状态先验 → 高 bull → 激进 EV」的自我引用。

**与软状态的关系**：状态方向 `state_dir` 与因子方向 `factor_dir` 按权重混合（本仓 `0.5/0.5`），
因子层面的多空可以**部分扭转**状态表的硬编码方向；但证据只通过 `confidence` 影响极化强度，
**不直接充当多空方向**（否则 `H` 偏空时 `confirming` = 看空，会被误判为看多——本仓踩过这个符号错误）。

### 4.7 状态迁移族

```python
FORWARD  = {(S0,S1),(S1,S2),(S2,S3),(S3,S4),(S4,S5)}
BACKWARD = {反向相邻}
REOPEN   = {(S3,S1)}      # 第二增长曲线：Late → Acceleration → 新预期差
kind     = stay / forward / downgrade / reopen / illegal
legal    = (from,to) ∈ FORWARD ∪ BACKWARD ∪ REOPEN ∪ {(s,s)}
```

**设计要点**：

- 迁移图是**领域知识**，不是数学推导的结果——「S1 能不能直接跳 S3」是业务判断（本仓：跳级非法）；
- `reopen` 这类特殊边必须**显式建模**，否则「第二曲线」会被误判为「非法跳级」；
- 迁移判定用**上一帧 argmax → 本帧 argmax**，不要用「分数差」，因为软状态的移动已经在 `drift` / `TV` 里；
- 同时输出 `trigger_factors`（`|方向分| > 0.3` 的活跃因子），让迁移有归因。

**软状态漂移的三个正交视角**（`diff.py`）：`mass_delta`（逐状态质量流动）、`tv_distance`（总位移）、
`entropy_delta`（变确定 / 变模糊）。三者分开表达，才能区分「整体平移」和「越来越拿不准」。

### 4.8 决策映射族：类型 / 力度 / 门槛三轴

```python
动作类型 = ARGMAX_MAP[state.argmax_state]              # S0 观察 / S1 试探 / S2 加仓 / S3 核心 / S4 减仓 / S5 清仓
力度     = Σ P_s · midpoint(weight_band[s])             # 软状态期望（熵高 ⇒ 力度天然保守）
stock_w  = base_budget × 力度 × confidence × risk_mult × portfolio_adj
门槛     = EV < 阈值 ? (低熵且为负 ? 压 0 : × 0.3) : 不动
标签     = reverse_band(折减后实际仓位)                  # 标签必须由「折减后」的实际仓位反推
```

四个可复用的规则：

1. **禁止 `if state == "S2": buy()`**：动作类型只给「意图锚点」，力度必须来自**分布期望**，
   这样熵高的帧自动更保守（不确定性本身在压低仓位，不需要额外规则）。
2. **三轴相乘，不求和**：类型（离散）× 力度（连续）× 门槛（赔率）。求和会混淆量纲，也会让
   「状态好」抵消「赔率差」。
3. **门槛要软硬分层**：EV 不足时**减仓（×0.3）**，只有「EV 为负 **且** 低熵（高置信确认负面）」才压 0。
   高熵时不清仓，才是「不确定性降低动作力度」的正确表达。
4. **标签由最终结果反推**：`position_band` 从 `actual_weight` 反推（例：`≥0.15 核心 / ≥0.10 加仓 /
   ≥0.05 试探 / >0 观察 / 0 清仓`）。用 `argmax` 直接当标签，会出现「核心」标签配 0.6% 实际仓位的背离
   ——本仓实跑踩过。

### 4.9 溯源 / 可审计算子

「可解释」不是事后写报告，而是**算子把中间量透出**：

| 算子 | 形态 | 解决的问题 |
|---|---|---|
| 分解字典 | `breakdown{原始值, 归一化项, 饱和标志, 各项修正, raw, f}` | 「这个分为什么是这个值」「是不是饱和了」 |
| 位掩码 | `source = 1/2/4`（营收腿/净利腿/质量腿） | 覆盖率统计、降级原因可诊断 |
| 具名原因 | `divergence_reason`（固定文案） | 下游可按文案匹配、进研究任务、进报告 |
| 结构对象 | `AdverseDivergence{severity, sf, se, price_strength}` | 「不同向」升级为「不利的不同向」，可排序 |
| 来源标签 | `probability_source` / `formula` / `mode` | 概率/公式/模式可溯源，回滚可验证 |
| 理由行 | `rationale: list[str]` | 人读的因果链，随结果落盘 |

**单一来源纪律**：F 的分解只由 `fundamental_breakdown` 计算，`_fundamental_trend` 只取其中的 `f`，
报告只读 breakdown——「决策算一份、报告再算一份」是双份真相的开始。

### 4.10 缺失值语义矩阵（最容易出错的一张表）

| 位置 | 缺失处理 | 语义 | 为什么不是别的 |
|---|---|---|---|
| `up/dn` 输入 | → `0` | 没有强度 | 取 0.5 会伪造强度 |
| `neutral_band` / `not_yet` 输入 | → `0.5` | 信息不足，给半分信用 | 取 0 会把「待补」误判为「已否定」（低覆盖标的 E 常为 `None`，取 0 会让「价格先确认」逻辑直接失效） |
| `severe` 输入 | → `0` | 不制造证伪证据 | 取 0.5 会凭空给出「已证伪」 |
| `saturate` 项 | **不参与均值**（不补 0） | 缺失不稀释 | 补 0 = 把「不知道」当成「中性」 |
| 整轴方向分 | → `None`（不进 L2 公式） | 显式缺失 | 让证据层看到「没有这一轴」，而不是 0 分 |
| 一致预期覆盖 < 3 | E → `None`，并登记 `missing_facts` | 不可信的修正不如没有 | 用低覆盖数据算上修 = 噪声当信号 |
| 估值分位缺失 | EV → `None`，注明降级原因 | 不猜收益 | 猜 R 会让 EV 看似可用 |
| 市场暴露缺失 | `actual_weight=None`，标签回退 `stock_weight` | 显式缺失 + 保守回退 | 回退 0 会让仓位凭空清零 |

**原则**：`0` = 无证据（不给信用）；`0.5` = 信息不足（半分信用）；`None` = 显式缺失（不参与 + 留痕）。
**禁止第四种：静默回退成 0/中性然后不声张。**

### 4.11 按目的选算子（速查）

| 你想要的语义 | 用这个 |
|---|---|
| 压到 `[-1,1]`，超阈值即饱和 | `saturate(v, scale)` |
| 压到 `[-1,1]`，但保留大幅值差异 | `log1p_saturate(v, log1p(ref))` |
| 分位 → 有符号（低分位=有利） | `1 - 2p` |
| 排名 → 有符号（越前越拥挤） | `-saturate(100 - rank, 100)` |
| 「接近中性」钟形 | `neutral_band(x, w)` |
| 「尚未发生」单侧 | `not_yet(x, w)` |
| 「严重到某程度」带死区 | `severe(x, lo, hi)` |
| 「全部满足」 | `min` 或乘积 |
| 「至少一条路径」 | `max` |
| 「同向证据累加」 | 加权和（**仅同状态内部**） |
| 多源同质指标合成 | 缺失感知均值 |
| 双锚点合成、允许单侧全额 | 加权 + 单侧承载回退 |
| 让状态间可比 | 除以可达上限 `cap` |
| 变成分布 | `softmax(n / τ)` |
| 度量不确定性 | `H_norm` / `P_top` |
| 度量位置变化 | `drift` / `TV distance` |
| 概率 ↔ log-odds | `logit` / `sigmoid` |
| 证据强度 → 概率更新 | 似然比 `(1+d)/(1-d)` |
| 防饱和到 0/1 | `clamp(p, 0.05, 0.95)` |
| 分数 → 动作 | `argmax → 类型` + `ΣP·band → 力度` + `阈值 → 门槛` |
| 动作标签 | 由**折减后**实际仓位反推 |

## 5. 不变量与测试契约（怎么证明这个模型是对的）

模式的可信度来自**形式化的不变量 + 能杀死错误实现的测试**，不是来自「看起来合理」。

### 5.1 不变量清单（I1–I9，本仓已实现）

| 编号 | 不变量 | 形式化陈述 | 测试 |
|---|---|---|---|
| I1 | 对抗性单调性 | F/E 沿负方向移动：多头侧（S0–S3）证据**不增**、空头侧（S4/S5）**不降**；分布层只断言可证的聚合量（多头总质量不增、看空质量不降） | `test_i1_adverse_monotonicity` |
| I1b | 跨零单调 | E 从 `+0.05` 单调降到 `−1.00`：多头侧证据不增；且 `S2(+0.05) > S2(−1.0)` | `test_i1b_monotonicity_across_zero` |
| I2 | 可达性 | 每状态都存在输入使其成为 `argmax` 且 `P_top ≥ 0.65` | `test_i2_reachability_all_six_states` |
| I3 | 幅度敏感性 | 同一轴取不同幅度（`−1` vs `−0.5`）必须产生可观测的分布差异（≥ 容差），且 `S2` 证据随 E 幅度变化（证明不是只看符号） | `test_i3_magnitude_sensitivity` |
| I3b | 关键格不反转 | 关键格（`F≤−0.5 ∧ E≤−0.3 ∧ T≥0.3`，1000 格）中「空头质量 ≥ 50%」的比例 ≥ 90% | `test_i3b_critical_cell_not_inverted` |
| I4 | 上限一致性 | 每状态可达 cap；网格上任何输入 ≤ cap；`cap(S5) == max(1.5, BREAK_LAMBDA)` | `test_i4_*` |
| I5 | 校准聚合 | 完美多空 `P_top` 差 ≤0.10；无信号帧 `P(S0) ≥ 0.85`；`H_norm ∈ [0,1]`；`ΣP = 1` | `test_i5_calibration_*` |
| I6 | 语义边界 | 「仅 F 崩」（预期未下修）= 反转候选，不退出；「F+E 双击」= 退出 | `test_i6_turnaround_vs_falsification` |
| I7 | 结构化背离 | 顶背离帧 `severity = sf·se·t_up`，非顶背离帧为 `None`（不产空对象） | `test_i7_adverse_divergence_object` |
| I8 | 不确定性语义 | `P_top` 低；顶背离**不算** uncertain；非顶背离的背离算 uncertain；**每个 uncertain 帧必有研究任务** | `test_i8_*` |
| I9 | 无假均分 | 任何输入 `max(evidence) > 0`，分布不出现 6 状态各 1/6 | `test_i9_no_zero_evidence_uniform` |

### 5.2 测试的三层结构（可直接照搬）

| 层 | 内容 | 本仓落点 |
|---|---|---|
| **不变量**（性质测试） | I1–I9：网格 / 扫描 / 构造 witness；不依赖真实语料 | `test_classifier_v2.py` |
| **变异杀伤**（判别力自证） | 把实现故意改错（单边门控、去归一化、S5 单路径、去底噪、改因子方向），断言**至少一个测试变红** | `test_classifier_v2_parity.py::test_mutation_kill_*` |
| **零回归**（演进安全） | v1 golden JSON 逐值不变；v1/v2 共享常量与迁移集合逐值相等（parity 钉） | `test_v1_artifact_golden.py` / `test_classifier_v2_parity.py` |
| **接线**（契约传播） | producer → consumer 每字段有真实消费者；additive 字段默认值回落；序列化不升版本 | `test_decision_model.py` / `test_classifier_v2.py` 尾部 |

**断言判别力纪律（本仓踩过的坑）**：I1 的扫描域是负域，而「把双侧算子换回单边」的变异在负域上是**常数**，
I1 按定义杀不掉它。正确做法不是放宽 I1，而是**新增 I1b 覆盖「正→负」过渡**，并在 ROADMAP 里如实登记
「该变异在 I1 的域上不可观测，由 I1b 收口」——**等价变异体不能计入杀伤数**。

### 5.3 验收帧（固定输入 → 固定输出）

除了性质测试，还要有**少量高价值真实帧**的端到端期望值（`P_top` / `H` / 关键质量容差 ±0.02）：
「600760 实帧 → S5 / P_top≈0.843」「完美多头 → S3 / 0.868」「无信号帧 → S0 / 0.869」
「完美空头 → S5 / 0.788」「顶背离典型 → S5 / 0.944」「困境反转 → uncertain、不退出」。
这些帧是**设计语义的锚点**，改动公式/参数后它们必须一起被复核——验收帧变了，就说明语义变了。

## 6. 参数与版本治理

### 6.1 常量分四类，不要混

| 类别 | 例子 | 可调？ | 放哪 |
|---|---|---|---|
| **结构常量** | `EVIDENCE_CAPS`、状态元组、迁移集合 | ❌ 不可调（改 = 改模型） | 模块顶部常量 + 导入期断言 |
| **校准参数** | `TEMPERATURE`、`UNCERTAIN_P_TOP`、`BREAK_LAMBDA`、`W_*`、`SEVERE_*`、`S0_*` | ✅ 只能走校准规程 | `EvidenceParams`（frozen dataclass）+ `DEFAULT_PARAMS` |
| **共享阈值（与旧版同值）** | `_UP_T`、`_DOWN_T`、`_ACTIVE_T`、`_DRIFT_EPS` | ❌ 冻结（parity 钉） | 私有常量 + 同名别名供测试钉 |
| **运行参数** | `order`、`previous`、`params`、`marginal_mode` | — | 调用时 keyword 传入 |

**为什么校准参数要放进 dataclass 透传**：回测/校准要「不改模块常量复算」，frozen dataclass 既不可变
（不会被下游偷偷改）又能整包透传；所有入口（`classify_state` / `state_evidence` / `distribution`）
共享同一个 `params`，避免「一半用新参数一半用旧参数」。

### 6.2 校准规程（唯一允许调参的通道）

```text
1. 语料门：真实帧 ≥ 50 才允许做分位数类校准（不足 ⇒ 降级：只跑形状约束，参数保留初值并登记「待校准」）
2. 温度 τ：只用形状约束（完美多空 P_top 差 ≤0.10；实帧 P_top 不能塌）
3. 不确定性阈值：必须在 τ 冻结后标定（用 P_top 分位）
4. 多路径权重 λ：用「关键格 argmax 占比 ≥ 90%」+「仅 F 崩帧 S5 ≤ 0.2」双约束夹可行域
5. 聚合复核：以容差（±0.05）重跑 I5 的门；容差不放宽门本身
6. 冻结留痕：参数值 + 语料口径 + 每条约束的实测数写进常量区注释，测试用 pytest.approx 钉死
```

**关键教训**：校准规程本身可能不自洽。本仓遇到两处——(a) 三个候选约束对 τ 同向单调，按字面「取裕度最大者」
会恒取最小候选，与设计冻结值矛盾；(b) 「仅 F 崩」帧对 λ 不敏感（`se == 0` 时证伪项恒 0），所谓「上界不成立」。
处理方式：**按可行下界保留默认值 + 在 ROADMAP 登记规则表述缺陷**，而不是偷偷改规格或硬凑参数。

### 6.3 版本演进治理

| 规则 | 做法 | 验证手段 |
|---|---|---|
| 旧版冻结 | v1 模块一行不改，只在 docstring 写明「冻结」 | v1 golden 逐值不变 |
| 新版唯一演进 | v2 是唯一演进分支；新增功能只进 v2 | 模块自包含测试（AST 检查不 import v1） |
| 防双实现漂移 | 共享常量 / 迁移集合 / 中性算子由 parity 测试**逐值钉同值** | `test_shared_*_equal_v1` |
| 切换 fail-open | 配置非法/缺失/异常 → warn + 缺省值，绝不抛；缺省 = 旧行为 | `test_classifier_dispatch.py` |
| 回滚一行 | 回滚 = 改一个配置值（`formula_revision: v1`），不 revert 代码 | 显式 opt-in 设计 |
| 契约 additive | 新字段全部带默认值、`schema_version` 不升、旧 JSONL 反序列化回落 | 旧帧 `model_validate` 测试 |
| 门禁显式 | 新公式先 shadow（算但不生效）→ 语料门通过 → 才 on | 模式枚举 + 冻结参数钉 |

### 6.4 什么该进 config，什么不该

- **该进**：选择哪套公式 / 哪种顺序 / 是否启用影子模式（影响行为但**不改变数值口径**）。
- **不该进**：`TEMPERATURE`、`cap`、`W_*`、`SEVERE_*` 这类校准参数——它们必须过校准规程并留痕，
  一旦开放给 config，就会变成「线上随手调参」，回测与历史帧全部失去可比性。

## 7. 反模式与病历（从 v1 到 v2 的真实缺陷）

每个缺陷都值得当成通用警钟，因为它们**都不是调参能修的**。

### D1 单边门控导致「恶化 = 确认」（符号方向错误）

- **症状**：某轴越负，该轴所在的多头状态证据反而越高（v1：E 越负 → S1 越高；tef 的 S2 同理；
  etf 则是 T 越负 → S2 越高）；「恶化」被当成「确认」。
- **根因**：「尚未上修 / 尚未共振」这类**接近度语义**用了单边 `not_up`，而语义要求是**双侧中性带**。
- **修法**：`neutral_band` 替换单边算子；并用 I1b（跨零过渡）钉住 —— 只看符号的 I1 在负域上杀不死这个变异。
- **通用规则**：**门控项的双侧/单侧由语义决定**；「尚未达到」单侧，「接近中性」双侧。

### D2 单一门控导致出口数学不可达

- **症状**：v1-tef 在 `T ≥ 0` 时 `S5 ≡ 0`，退出在数学上不可达（「价格还在涨就不可能退出」）。
- **根因**：S5 被 `t_dn` 独占门控；而「造假 / 政策突变 / 基本面双击」可以在价格还没跌时发生。
- **修法**：`S5 = max(价格路径, BREAK_LAMBDA·se·sf)`——两条独立路径取 `max`，且证伪路径不含 `T`（与顺序解耦）。
- **通用规则**：**每个「出口/终态」至少要有一条不依赖单一轴的到达路径**，并用 I2 可达性钉住。

### D3 上限不齐导致 softmax 内建状态先验

- **症状**：S3 天生最高 3.0、S5 最多 1.5、S0 恒 0.30；softmax 自动偏向大 cap 状态；熵不可跨状态/跨帧比较。
- **根因**：证据公式量纲不同却直接进 softmax。
- **修法**：先除以每状态可达上限，再 softmax；cap 由「门控 × 系数和」推导 + witness 帧验证 + 导入期断言耦合关系。
- **通用规则**：**任何进 softmax 的量都必须先做「同尺度化」**；否则量纲差 = 隐式先验。

### D4 熵-only 的不确定性，且与「坏消息」混用

- **症状**：`uncertain = 熵高 or 背离`，语义混乱；出现「uncertain=True 却没有任何研究任务」的孤儿帧。
- **根因**：一个布尔值承担了两种相反语义——「不知道」（该研究）与「知道是坏的」（该减仓）。
- **修法**：`uncertain = (P_top < 阈值) or (有背离但不是顶背离)`；顶背离单独建模为 `AdverseDivergence`
  （「确定的坏消息」），产出高优先级研究任务，不算 uncertain。
- **通用规则**：**不确定性与负面性必须分开**；每个「不确定性」都要有**可执行产出**（研究任务/降级标记），
  否则就是孤儿信号。

### D5 底噪的「恒定比较优势」

- **症状**：S0 在 55.5% 的网格帧上占 argmax，其中明确偏多的帧仍占 29.0%。
- **根因**：归一化后 `n(S0) = floor + (1-floor)·neutrality ≥ floor`，底噪是**与输入无关的下限**，等价于
  在 logit 上给 S0 加了一个常数偏置。
- **修法**：把 floor 从 0.30 降到 0.10（只保留「矛盾 ⇒ 研究候选」语义）。
- **通用规则**：**任何进入分布前的常数项都会变成比较优势**；加常数前先问「它是否应该随输入变化」。

### D6 多路径相加导致双重计数

- **症状**：价格破位 + 双击证伪同时满足时，S5 证据被重复放大。
- **修法**：`max` 而非 `+`；两条路径各自保持单调。
- **通用规则**：**「或」的语义要用 `max`，「且」用 `min`/乘积，「同向累加」才用加法**。

### D7 cap 归一化放大小 cap 状态

- **症状**：S0 原始证据 0.106（S2 的 1/5），归一化后 0.354 反超 S2 的 0.282。
- **根因**：除以小 cap 会把「小量」放大；cap 必须是真实可达上限，不能为了平衡拍数字。
- **通用规则**：**归一化会改变排序**；cap 取值必须有 witness 帧与网格上界双重证明。

### D8 `if state == "S2": buy()` 反模式

- **症状**：动作类型与力度混在一起，熵高时仍然满仓；「核心」标签配 0.6% 实际仓位。
- **修法**：类型（argmax 映射）+ 力度（`ΣP·band`）+ 门槛（EV/置信度）三轴相乘；标签由折减后实际仓位反推。
- **通用规则**：**状态只回答「现在是什么局面」，不回答「下多大注」**。

### D9 双实现漂移 / 两份真相

- **症状**：v1/v2 各写一份阈值；报告与决策各算一份指标；下游重算上游已算好的量。
- **修法**：共享常量由 parity 测试逐值钉同值；中间量透出（`state_evidence` / `breakdown` / `divergence_reason`），
  下游只读不算；「唯一计算入口」写进 docstring。
- **通用规则**：**同一语义只允许一个计算点**；跨实现共享的量必须被测试钉死。

### D10 静默 0 回退

- **症状**：某轴缺失 → 当作 0 → 该轴证据「中性」→ 状态被静默判成「没有信号」。
- **修法**：缺失分层（§4.10）：`None` 不进公式、0.5 表达「信息不足」、0 表达「无证据」，并在 artifact 里留痕。
- **通用规则**：**缺失是数据事实，不是数值 0**。

### D11 孤儿不确定

- **症状**：`uncertain=True` 但没有研究任务/降级标记，下游不知道该干什么。
- **修法**：每个不确定来源各配一个可执行产出（本仓：`research-adverse` / `research-divergent` /
  `research-uncertain`），并由测试断言「uncertain ⇒ 至少一个任务」。
- **通用规则**：**没有消费者的信号 = dead-end**（契约传播纪律）。

## 8. 复用指南：在新领域落地这个模式

### 8.1 十步法

1. **定义状态族**：入口 / 过程（按生命周期）/ 出口；保证每个状态都有对应动作语义；出口至少两条路径。
2. **选轴并统一符号**：每个轴回答「对结论有利 = 正」；列一张「轴 → 业务含义 → 单位 → 缺失率」表。
3. **逐轴压方向分**：选 `saturate` / `log1p_saturate` / 分位映射 `1-2p` / 排名映射；缺失 → `None`。
4. **逐状态写语义**（先用中文，不写公式）：这个状态的「时机门控」是什么？「支撑证据」有哪些？
   「什么情况下不成立」？——写成 G/S/V 三栏，评审通过后再落公式。
5. **推导 cap**：`cap = 门控上限 × 支撑系数和`（乘法型/加法型分别算）；构造 witness 帧验证可达。
6. **归一化 + softmax + 温度**：先跑网格确认「每状态可 argmax、无假均分、熵有区分度」。
7. **定义不确定性与具名冲突**：用 `P_top` + 结构化背离；每个出口配可执行产出（研究任务/告警/降级）。
8. **动作映射**：类型（argmax）/ 力度（分布期望 × 置信度 × 风险）/ 门槛（赔率、流动性、上限）；
   标签由最终实际量反推。
9. **写不变量测试**：I1–I9 家族 + witness 帧 + 验收帧 + 变异杀伤；参数按校准规程冻结并留痕。
10. **契约传播**：新字段 additive + 默认值 + 单一来源 + 真实消费者；旧数据可反序列化、可一行回滚。

### 8.2 模板骨架（与具体领域无关）

> 骨架示意：`...` 为待填占位，删除空实现的 `...` 才能运行；`transition_of` / `result` 是需要你补的
> 迁移判定与结果载体构造。

```python
from dataclasses import dataclass
import math

STATES = ("S0", "S1", "S2", "S3", "S4", "S5")
CAPS = {"S0": ..., "S1": ..., ...}          # 结构性常量，导入期自检

@dataclass(frozen=True)
class Params:                                # 校准参数集中、不可变、整包透传
    temperature: float = ...
    uncertain_p_top: float = ...

DEFAULT = Params()

def clip01(x: float) -> float: ...
def up(x: float | None) -> float: ...                        # 缺失 → 0
def dn(x: float | None) -> float: ...                        # 缺失 → 0
def neutral_band(x: float | None, w: float) -> float: ...     # 缺失 → 0.5
def not_yet(x: float | None, w: float) -> float: ...          # 缺失 → 0.5
def severe(x: float | None, lo: float, hi: float) -> float: ...  # 缺失 → 0

def evidence(scores, *, params=DEFAULT) -> dict[str, float]:
    """每状态独立打分：G(门控) × S(支撑) × V(否决)；不跨状态求和；缺失不造证据。"""
    ...

def normalize(ev: dict[str, float]) -> dict[str, float]:
    return {s: clip01(ev[s] / CAPS[s]) for s in STATES}

def distribution(norm: dict[str, float], *, params=DEFAULT) -> dict[str, float]:
    logits = {s: norm[s] / params.temperature for s in STATES}
    peak = max(logits.values())
    w = {s: math.exp(v - peak) for s, v in logits.items()}
    total = sum(w.values())
    return {s: v / total for s, v in w.items()}

def classify(scores, *, previous=None, params=DEFAULT):
    ev = evidence(scores, params=params)
    norm = normalize(ev)
    dist = distribution(norm, params=params)
    argmax = max(dist, key=dist.get)
    entropy = -sum(p * math.log(p) for p in dist.values() if p > 0)
    p_top = max(dist.values())
    uncertain = p_top < params.uncertain_p_top        # + 具名背离等其它来源
    transition = transition_of(previous, argmax, scores)  # 迁移图 + kind + trigger
    return result(dist, argmax, entropy, p_top, uncertain, transition, norm)
```

### 8.3 落地 checklist（20 条）

- [ ] 每个轴都写了「正 = 有利」的业务含义，且能独立取到数
- [ ] 方向分缺失返回 `None`，没有任何地方静默补 0
- [ ] 每个状态都能用一句「门控 / 支撑 / 否决」说清
- [ ] 门控项的双侧/单侧由语义决定（「接近中性」≠「尚未发生」）
- [ ] 所有 `[0,1]` 门控都保证非负；可能出现反证据的算子已在 docstring 声明并由归一化收口
- [ ] 每个状态的 cap 有推导 + witness 帧 + 网格上界证明
- [ ] 状态之间没有 `Σwᵢ·xᵢ` 式的跨状态求和
- [ ] 「或」用 `max`、「且」用 `min`/乘积，同向累加才用加法
- [ ] 底噪/常量项的量级经过检验（归一化后不构成恒定比较优势）
- [ ] 每个状态在网格上都能成为 argmax（可达性）
- [ ] 任何输入都不会出现「全零 → 均分」假高熵
- [ ] 不确定性有可执行产出（研究任务/告警/降级标记），没有孤儿信号
- [ ] 「不知道」与「知道是坏的」分开建模（不确定性 ≠ 负面性）
- [ ] 温度/阈值用聚合门标定，不是看图调参；语料不足时登记「待校准」
- [ ] 参数分四类（结构/校准/共享/运行），结构常量有导入期断言
- [ ] 动作类型、力度、门槛三轴分离；没有 `if state == X: buy()`
- [ ] 动作标签由折减后的最终量反推，不直接用 argmax
- [ ] 中间量（证据/分解/原因/来源）透出给下游，下游不重算
- [ ] 不变量测试覆盖单调性、可达性、幅度、上限、校准门；变异实验能变红
- [ ] 版本可一行回滚，旧数据可反序列化，默认行为零变化

### 8.4 什么时候该放弃

- 需要的是**精度**不是**相位**（例如预测收益率幅度）→ 回到连续模型，状态只做辅助解释。
- 轴之间存在强**共线性**（信息高度重叠）→ 模式证据会重复计数，应先做正交化/降维。
- 状态定义本身**不稳定**（业务方每季度改口径）→ 先治理口径（`alphabee-schema-steward`），再谈状态机。
- 没有语料也**不打算校准** → 至少保留「结构性常量 + 显式待校准登记」，不要把拍脑袋参数伪装成校准结果。

## 9. 把模式扩展到 Agent 开发：原子算子 + LLM 生成表达式

> **本章回答第三个问题**：这套「原子算子 + 组合」的做法，能不能让 LLM 根据自然语言生成复杂表达式，
> 既保留泛化能力，又控住计算准确性？
>
> **结论：能**，但必须把 LLM 的角色限定为「自然语言 → 受控表达式结构」，数值计算全部交给确定性原子；
> 并且生成之后要有**编译 → 测试 → 影子**三道门禁。这是目前「LLM 泛化」与「计算可控」之间性价比
> 最高的一条路——代价是原子库要持续维护。

### 9.1 一句话结论与三个前提

**LLM 负责「把话翻译成结构」，原子与运行时负责「结构算得对」，测试与门禁负责「结构真的对」。**

三个前提（缺一不可）：

1. **原子语义正确且被测试钉住**——否则 LLM 组合得再对，也是在错的基上放大错误。
   本仓的 D1 就是「原子语义错」的样板：单边算子被当成「接近中性」，组合得越复杂错得越远。
2. **DSL 受限且类型化**——白名单节点 + 名字白名单 + 类型/单位检查 + 规模上限，把语法错、注入、
   失控表达式挡在编译期。
3. **生成后有门禁**——类型检查、契约测试、语义验收帧、影子 A/B，全过才准生效。

两个来源必须分清，否则会做出「看起来能泛化、实际在拍脑袋」的系统：

- **泛化能力来自「原子库的闭包 + 组合」**，不是来自 LLM 的算术；
- **准确性来自「表达式受限 + 求值确定 + 测试门禁」**，不是来自更长的 prompt。

### 9.2 把「准确性」拆成四个维度

| 维度 | 保证强度 | 靠什么 | 残余风险 |
|---|---|---|---|
| **可复现 / 确定性** | 强 | LLM 只出结构；求值是纯函数；同一表达式 + 同一输入必然同一输出，可回测 | 原子版本漂移 ⇒ 靠原子版本化与 golden 收口 |
| **值域 / 数值稳定** | 强 | 原子自带值域、饱和、死区、除零与缺失口径 | 组合后的极端值 ⇒ 靠值域静态推导 + 网格测试 |
| **可审计 / 可回归** | 强 | 表达式是**数据**：能 diff、能版本化、能 shadow、能一行回滚 | provenance 记不全 ⇒ 版本三元组（§9.5 第 8 条） |
| **语义正确性** | 部分 | 名字即语义 + 契约测试 + 人工验收帧 + 影子 A/B | **选错算子 / 符号反 / 单双侧错**——LLM 生成最主要的错误类型，只能靠测试与评审兜 |

**结论**：前三维是工程保证，可以直接交给运行时；第四维必须承认它是**测试与评审问题**，
不能外包给模型——这正是 §5 的 I1–I9 与 §7 的 D1–D11 在 Agent 时代仍然必要的原因。
与「只加 prompt / skills」的完整对照见 §9.11。

### 9.3 三层分工与数据流

```text
自然语言需求（人写 / 上游 agent 产出）
   │        ← LLM 只做这一层：语义翻译（选原子、定结构、填参数）
   ▼
受限表达式（JSON AST，不是 Python 源码）
   │        ← 编译器：解析 → 类型检查 → 值域/缺失检查 → 规模检查
   ▼
确定性运行时（纯函数求值 + provenance）
   │
   ▼
测试门禁（契约测试 / 验收帧 / 影子 / golden）→ 生效 / 拒绝 / 转人工
```

**为什么用 AST/JSON 而不是表达式字符串**：

| 原因 | 说明 |
|---|---|
| 无歧义 | 字符串要处理优先级、括号、函数白名单与转义，JSON 结构天然唯一 |
| 可类型检查 | 能逐节点推导类型与值域，错误可定位到 `$.args[2]` |
| 错误可回灌 | 结构化错误（`expected` / `actual` / `suggestion` / `candidates`）是 LLM 收敛的关键 |
| 可 diff / 可审计 | 表达式作为数据，能存库、比对、版本化、回滚；字符串只能整段替换 |

若沿用字符串 DSL（本仓现状，见 §9.8），至少要做到：**名字白名单 + 函数白名单 + 深度/节点上限**。

### 9.4 原子契约：准确性的真正载体

原子不是「一个函数」，而是「一份契约」。LLM 能看到、编译器能检查、测试能验证的，都是这份契约：

| 字段 | 例子 | 作用 |
|---|---|---|
| **名称即语义** | `neutral_band`（双侧）/ `not_yet`（单侧）/ `severe`（负侧死区） | 把 §4.3 的选型判据编码进名字——这是治 D1 的治本手段 |
| 签名与类型 | `(Score, Width01) -> Unit` | 编译期挡类型错 |
| 值域 | `[0,1]` | 组合后仍可静态推导（能抓「Unit 和 25 比大小」这类量纲错） |
| **缺失策略** | `None → 0.5`（信息不足）/ `None → 0`（不造证据）/ `propagate` | 不允许默认静默 0（§4.10 的机器可执行版） |
| 单调性 / 对称性 | `neutral_band` 对 `abs(x)` 单调不增；`severe` 对 `x` 单调不增 | **能自动生成 property test**，这是防符号错误的核心 |
| 纯度与成本 | pure、O(1)、无 IO | 可缓存、可批量、可并行 |
| 示例 / 反例 | docstring 里的 fixture | 同时喂给 LLM（few-shot）与测试（验收帧） |
| 版本 | `neutral_band@2` | 语义变更可追溯、可回滚；表达式记录所用原子版本 |

两条设计纪律：

1. **泛化的天花板 = 原子库的闭包**。如果需求需要「5 年分位」而库里只有 `mean`，LLM 会拿 `mean`
   近似，静默丢掉语义。所以必须给它一个**诚实的出口**：`request_new_atom(reason)`——表达
   「现有原子无法表达」。这比让它硬凑近似重要得多，也是「泛化边界」唯一诚实的做法。
2. **原子语义变更 = major 版本**。改一个算子的语义会同时影响所有引用它的表达式；原子库的变更
   成本与 §6.3 的 `v1 冻结 / v2 演进` 是同一类治理问题，应沿用同一套 parity/golden 纪律。

### 9.5 DSL 的八条硬约束

| # | 约束 | 现状（本仓） |
|---|---|---|
| 1 | **节点白名单**：`Name / Constant / BinOp / UnaryOp / Compare / BoolOp / 白名单 Call`；禁属性访问、下标、lambda、推导式、赋值、import、循环 | 已有：`registry.py:10-32` 白名单 + `:98` 拒绝其余节点 |
| 2 | **名字白名单**：字段来自 schema registry、函数来自 atom registry，其余一律拒绝 | 已有：`registry.py:47-50` 未知变量 raise |
| 3 | **类型 / 单位**：`Percent / CNY / Ratio / Score / Rank` 不可混加；比较只允许同域 | **缺**：`schemas/*.yaml` 的单位注释需要升级为可检查的 domain |
| 4 | **空值显式**：表达式层声明 `none_policy`，原子自带缺失口径，二者不许互相覆盖 | 部分：`not_applicable_if` + 依赖 None 判定（`registry.py:164-196`），无表达式级策略 |
| 5 | **除零 / 越界用策略字段**，不靠 `try/except` 兜 | 已有：`zero_division_policy`（`registry.py:144`） |
| 6 | **规模上限**：节点数、深度、变量数（防表达式爆炸与「堆砌式过拟合」） | **缺** |
| 7 | **纯函数**：禁 IO、时间、随机、外部状态 | 求值器天然纯，但开放 `Call` 后需按函数签名强制 |
| 8 | **版本三元组**：表达式版本 + 原子库版本 + 输入 schema 版本一起冻结 | **缺** |

### 9.6 生成侧：编译器在环的 Agent 循环

Agent 的工具集应该是**编译器 + 测试器**，而不是「写文件的工具」：

| 工具 | 作用 |
|---|---|
| `list_atoms(query)` / `describe_atom` | 检索原子与契约（含示例、反例、缺失口径） |
| `build_expression(ast)` | 构造 / 替换子表达式（可做局部编辑，避免整段重写） |
| `typecheck(expr)` | 返回**结构化错误**：`code / path / expected / actual / suggestion / candidate_atoms` |
| `dry_run(expr, fixtures)` | 在验收帧上逐帧出值，返回「期望 vs 实际」 |
| `propose_acceptance_frames(nl)` | 让 LLM 出候选测试帧（人/规则确认后才入库） |
| `register_shadow(expr, meta)` | 注册为影子规则，带 provenance 与 atom_version |
| `request_new_atom(reason)` | 明确「无法表达」，转人工补原子 |

循环是：**NL → 候选表达式 → `typecheck` 错误回灌 → 修正 → `dry_run` 对照验收帧 → property test →
影子 → 门禁 → 生效**。三条工程建议：

1. **结构化错误消息的质量直接决定收敛速度**。错误里必须含「最接近的正确写法」和「可替代原子」：

   ```json
   {
     "code": "DOMAIN_MISMATCH",
     "path": "$.args[1].args[0]",
     "expected": "Unit",
     "actual": "Percent",
     "message": "severe() 输出 Unit，不能与 Percent 字段 e_revision 直接相加",
     "suggestion": "用 severe(e_revision)，而不是 e_revision",
     "candidates": ["severe", "dn", "neutral_band"]
   }
   ```

2. **语法引导解码**（JSON Schema / grammar-constrained decoding）能显著降低语法错误率，
   把模型的自由度压在「选哪个原子、怎么组合」上。
3. **生成在作者态、执行在运行态**：表达式是一次性生成、缓存、版本化的产物，不要每次请求现生成
   （除非只做「从库里选规则」这一档，见 §9.9 的阶梯）。

**一个具体例子**（NL → 表达式 → 两道门各自抓什么）：

需求：「价格仍强，但基本面与预期同时实质恶化 → 顶背离，不作为加仓证据」。对应 §3.3 的 S5 证伪路径：

```json
{"op": "mul", "args": [
  {"op": "severe", "args": [{"var": "f_fundamental_trend"}], "kwargs": {"lo": 0.25, "hi": 0.60}},
  {"op": "severe", "args": [{"var": "e_revision"}], "kwargs": {"lo": 0.25, "hi": 0.60}},
  {"op": "up", "args": [{"var": "t_relative_strength"}]}
]}
```

- **类型/值域检查能抓**：三个 `Unit` 相乘仍为 `Unit`；若阈值误写成 `25`（以为是百分比），
  值域检查报 `threshold out of domain: Unit expects [0,1]`；若把 `e_revision` 直接相乘，报
  `DOMAIN_MISMATCH`（Percent 与 Unit 混算）。
- **类型检查抓不到、只能靠验收帧的**：把 `severe` 换成 `dn`（语义从「实质恶化」降级为「有负向」）。
  必须补两条锚点帧：`F=−1, E=−0.5, T=+1 ⇒ ≈0.71`（`severe(−0.5)=0.714`）；`F=−0.2, E=−0.1, T=+1 ⇒ 0`（死区）。
  这就是 §5.3 验收帧在 Agent 时代的等价物。

### 9.7 验证体系：四道门 + 一个评测集

| 门 | 抓什么 | 成本 | 本仓对应 |
|---|---|---|---|
| **静态 / 类型检查** | 语法、类型、未知字段、规模 | 毫秒 | 现有节点白名单 + 未知变量拒绝；缺类型/规模 |
| **契约 / property 测试** | 单调性、值域、缺失、对称、边界 | 秒 | 原子契约自动生成；现状是手写 I1–I9 |
| **语义验收帧** | **选错算子、符号反、单双侧错** | 人写 3–5 帧 | §5.3 的验收帧 |
| **影子 / A/B** | 分布漂移、极端帧、与旧版不一致率 | 天 | `formula_revision` 双版本 + shadow 模式（§6.3） |
| **golden（回归）** | 任何改动导致的输出变化 | 每次提交 | `test_v1_artifact_golden.py` |

再建一个**评测集**（NL 需求 → 期望表达式 / 期望行为），量化四件事：`typecheck` 通过率、fixture
通过率、语义通过率、**「该说不会」的准确率**（`request_new_atom` 的 precision/recall）。用这个集子
迭代 prompt 与原子文档，而不是凭感觉调提示词。

**与 §5 的关系**：I1–I9 是「手写冻结实现」的验证方式。DSL 化之后，不变量要**下沉两层**——
原子层用契约测试（一次写、所有表达式受益），表达式层用验收帧（每条需求 3–5 帧）；
否则每新增一个表达式都要重写一套 I1–I9，维护成本会失控。

### 9.8 本仓现状与最小改造路径

**已有（等于路已经走了一半）**：

| 已有能力 | 落点 |

| 白名单安全求值器（拒绝未知节点/未知变量） | `alphabee/agents/derived_facts/registry.py:10-32`、`:35-100` |

| 语义算子已存在，只是冻结在代码里 | `classifier_v2.py:154-206`（`clip01`/`up`/`dn`/`neutral_band`/`not_yet`/`severe`）、`score_engine.py:129-146`（`saturate`/`log1p_saturate`/`_mean`） |

**缺的四件（按优先级）**：

1. **Atom registry**：把上表的语义算子注册进 DSL，带签名/值域/缺失/单调性/示例；
2. **类型与单位系统**：`schemas/*.yaml` 的单位注释升级为可检查的 domain，否则「Percent 与 Ratio 相加」无人拦；
3. **契约测试 + 验收帧执行器**：每个原子自动生成 property test；每条规则带 3–5 个验收帧；
4. **生成侧工具与结构化错误**：`build / typecheck / dry_run / request_new_atom`。

- 新建 `alphabee/dsl/`：`atoms.py`（原子 + 契约）/ `types.py`（domain 与值域）/ `compiler.py`（解析与检查）/
  `properties.py`（契约测试生成）/ `registry.py`（注册与检索）；
- 规则 YAML 增补三个字段：`atom_version` / `none_policy` / `acceptance_frames`；

- **立一条 parity 纪律**：DSL 版算子必须与 `classifier_v2` 的冻结实现逐值相等（沿用

- 先做**数值合成类**规则（衍生事实、信号阈值），**不要一上来做仓位/交易规则**。

### 9.9 从「更可控」到「更泛化」的四级阶梯

同一件事有四种做法，控制力依次下降、泛化力依次上升，**按需求选级，不要一步跳到第 4 级**：

| 级 | 做法 | 控制力 | 适用 |
|---|---|---|---|
| T0 | 固定规则库，LLM 只**选**规则 | 最高 | 高频、口径稳定、不允许偏差 |
| T1 | 模板 + LLM **填参数**（受限字段） | 高 | 参数化规则（阈值、窗口、权重） |
| T2 | **受限 DSL 组合**（本章目标） | 中高 | 长尾需求、规则爆炸、需要按语境定制 |
| T3 | LLM 直接生成可执行代码 | 低 | 一次性分析脚本，**不进生产决策链** |

本仓的 `derived_facts` / `signal` 现在在 T0–T1 之间，目标是 T2；T3 只有沙箱内的一次性脚本。

### 9.10 什么时候不要用

- **定性语义判断**（管理层是否可信、政策冲击多大）：不要硬编成公式，走结构化判读 + 受控 judge
  （`SEMANTIC_JUDGMENT_CONTRACT_DESIGN.md`）；
- **需要拟合的数字**（权重、阈值、温度）：不要让 LLM 生成数字，走 §6.2 的校准规程；
- **高风险执行链**（下单、真实仓位）：表达式只能产「建议」，执行必须有人工/规则门禁——
  不能把 LLM 生成的表达式直接接到执行链；
- **数据契约还没治理好**：表达式再对，输入是错的也白搭（先补 schema / 缺失治理，见 §4.10）。

### 9.11 与「只加 prompt / skills」的对照（结果与工程双维度）

> 本节是**对照分析**，不是「二选一」提案：prompt / skills 是语义前端的正解，真正的分歧只在
> 「计算由谁执行」。把这一点写清楚，后面每条优势判断才有意义。

#### A. 比较对象与一个关键区分

| 记号 | 执行机制 | 计算由谁完成 | 典型形态 |
|---|---|---|---|
| **P**（prompt-only） | LLM 直接产出结论 / 数值 | token 预测 | 系统提示词里写判据，模型直接给「S2 / 加仓」 |
| **S**（skills-only） | LLM 按打包流程 / 清单执行 | 仍是 token 预测 | skill 写「先算 F，再比 E，最后查背离」，模型照做 |
| **D**（原子 + DSL，§9.1–9.10） | 受限表达式 + 确定性求值 | 纯函数 | 模型只出表达式结构，数值由编译器 / 运行时算 |

> **关键区分不是「有没有 prompt/skills」，而是「计算由谁执行」**。P/S 改变的是模型的**先验**
> （它更可能往对的方向走），D 改变的是**执行器**（错的结构根本跑不起来）。二者不在同一层面竞争：
> P/S 提供的是**概率**，D 提供的是**性质**。
>
> 一个常见混淆：skills 里一旦出现「调用脚本 / 工具」，其实已经在做 D 了，只是把原子藏在工具里。
> 真正的问题永远是：那次计算有没有落到确定性代码上。

#### B. 结果维度：用误差分类学比较，而不是用「准不准」

| 误差类 | 例子 | P / S | D | D 的机制 |
|---|---|---|---|---|
| **结构错** | 单位混算、除零、越界、语法与优先级、长表达式写崩 | 无法拦截，只能在输出里发现 | **编译期清零** | 类型/值域检查、白名单、规模上限 |
| **语义错** | 单侧算子当双侧用（D1）、符号反向、口径错 | 不可见、不可复现 | **同样会犯**，但变成可评审对象 | 名字即语义 + 验收帧 + 评审 |
| **数据错** | 输入缺失 / 错值 | 同样 | 同样 | （都靠数据契约，§4.10） |
| **知识错** | 前提假设本身不成立 | 同样 | 同样 | （靠研究流程，不靠机制） |

**结论 1**：D 不消灭语义错——它把错误空间从「四类」压到「三类」，并把语义错从**不可见的随机事件**
变成**可 diff、可评审、可测试的对象**。这是「结果可控」的真正来源，不是「模型更准」。

**（1）平均正确率 vs 尾风险**：P 优化平均正确率；D 不显著提高平均语义正确率，但**约束最坏情况**
（值域、单调、死区、缺失、除零都是「不可能越界」的性质，不是「大概率不越界」）。高频低风险、由人读
的输出，平均正确率就够；**资金决策的期望值由尾部决定**——「99% 正确 + 1% 灾难」与「95% 正确 +
最大损失有界」不是同一个东西。

**（2）偏差 vs 方差（D 的新风险，必须对称承认）**：

- P/S 的错误偏**方差型**：不同实例、不同运行、不同措辞错法不同，部分会相互抵消；
- D 的错误偏**偏差型**：一个原子语义写错，**所有实例同向错**，而且因为输出稳定反而更难被发现
  （「一直很稳定」会伪装成「一直很对」）；
- 推论：下游只做**排序 / 横截面比较** → 一致性比绝对准确更重要，D 占优（只要单调）；下游做
  **绝对阈值判断**（减仓 / 告警）→ 系统偏差是灾难，D 的前提是「原子语义被测试钉死」；
- 验证方法：拿同一帧扫一批标的，看错误是否同向——同向即偏差，随机即方差。

**（3）可复现 / 可回测 / 可校准**：P 受采样、模型版本、措辞、上下文长度影响；D 生成一次即冻结，
运行期 0 方差。模型升级时 P 是「全量行为静默漂移」，D 只影响生成这一步（离线重跑生成 + 编译 + 验收）。
D 才能做 §6.2 的网格扫描、温度标定、shadow A/B——**没有 D，校准规程根本无法执行**。P 对同一规则在
不同标的、时点会给出不同的「隐性阈值」；D 强制统一口径，排名才可比。

**（4）可审计 / 可回放 / 可归因**：D 的产物是数据（表达式 + 原子版本 + 输入 → 确定输出），可回放、
可逐节点定位、可对同一帧 diff 两版；P 的产物是文本，「上周同样的输入结论不同」无法解释，责任链断裂。

**（5）两种「泛化」要分开**：

| 泛化类型 | P / S | D |
|---|---|---|
| 措辞泛化（同义改写、新表述） | 强 | 弱（靠前端 LLM 做意图解析） |
| 组合泛化（原子闭包内的新组合） | 弱（长链算术 / 多约束容易崩） | 强（组合有类型与值域保护） |
| 超出能力边界 | 静默近似 ⇒ **错误不可见** | `request_new_atom` ⇒ **错误可见、可补** |

**结果维度小结**：

| 维度 | P / S | D | 优势成立条件 |
|---|---|---|---|
| 结构错 | 不可拦截 | 编译期清零 | 白名单与检查到位 |
| 语义错 | 不可复现 | 可评审、可测试 | **原子语义被契约测试钉死**，否则退化为系统偏差 |
| 尾风险 | 无界 | 有界（值域 / 单调 / 缺失） | 原子与组合都做了值域设计 |
| 可复现 | 有方差 | 0 方差 | 表达式与原子版本冻结 |
| 可校准 / 回测 | 不可行 | 可行 | 有评测集与校准规程 |
| 横截面一致 | 隐性漂移 | 强制统一 | 规则覆盖所有实例 |
| 泛化 | 措辞强 / 组合弱 | 措辞弱 / 组合强 | 前端 LLM 负责措辞解析 |

#### C. 工程维度：D 的优势主要不在准确率，在「可验证性」

**（1）验证成本（被低估得最厉害的一项）**：

| | P / S | D |
|---|---|---|
| 验证形态 | 统计评测（跑一批样本算准确率） | 单元 / property / golden（确定性） |
| 检测能力 | 「减少不知道」，不能证明没有 | 硬门禁：不过不许合并 |
| 成本量级 | 检出 2pp 回归约需 10³ 量级样本/轮，且 flaky | 每条规则 3–5 帧验收 + 原子 property，毫秒级 |
| 变更后 | 每次改 prompt 全量重跑 | 只跑受影响原子 / 表达式的定向测试 |

数量级说明（粗略）：估计比例 `p≈0.95`、允许误差 ±2%、95% 置信 → `n ≈ (1.96/0.02)²·p(1−p) ≈ 4.6×10²`；
若做 A/B（两个比例、80% 功效）→ 每臂 10³ 量级。**这是 D 最本质的工程优点**：把验证从**抽样问题**
变成**证明问题**。

**（2）变更管理与爆炸半径**：P 改一行可能影响所有输出，无法回答「这次改动影响什么」，也没有语义
版本；D 的表达式可 diff、可静态分析影响面（哪些规则引用该原子）、可 shadow、可一行回滚。本仓证据：
`formula_revision` 双版本 + v1 冻结 + parity 钉同值 + golden 快照——这套治理只能在 D 上成立。

**（3）运行成本、延迟与可用性**：

```text
C_P ≈ N_calls × (token + latency + 重试)
C_D ≈ N_authoring × C_gen + N_calls × O(μs) + C_infra
```

`N_calls` 越大、规则越稳定 → D 越省；但**真正的主导成本通常不是 token，而是错误成本与人工复核成本**。
D 可批量、可离线、可在 CI / 无网环境跑；P 依赖模型服务、供应商行为与配额。延迟上 D 是微秒级、P 是
秒级——这直接决定「能不能做回测 / 网格 / 大样本扫描」。

**（4）可观测性与排障**：D 透出中间量（`state_evidence` / `breakdown` / `divergence_reason`），可逐
节点求值、可算「两版规则在同一帧上的差异」；P 只有最终文本与推理链——**推理链不是证据**，它和被验证
的对象同源，无法用来证伪自己。

**（5）安全面**：P 面临 prompt injection、skill 文件篡改、自由文本输出难以做安全边界；D 有白名单、
无 IO / 无状态 / 无循环、规模上限，**生成与执行分离本身就是一层隔离**（即使生成被注入，执行仍受白名单
约束）。诚实边界：D 不解决数据投毒，只把攻击面从「任意执行」压到「受限表达式」。

**（6）组织与知识资产**：P 的知识在 prose 里——评审主观、随人走、专家无法验证「prompt 是否忠实于
业务口径」；D 的知识在原子契约与规则里——可评审（「这个阈值为什么是 0.25」）、可复用、可统计覆盖率、
可移交。规则数过几十条后，P 的规则会隐性冲突且不可检测；D 的冲突是结构化的（同字段、重叠条件、依赖环）。

**（7）前期成本与规模效应（D 的唯一大劣势）**：P 零前期成本、边际成本低；D 前期成本高（类型系统、
原子库、编译器、测试基建），但边际成本随原子覆盖率下降。打平条件（符号化）：

```text
D 更优 ⇔ M × (V_p − V_d) + (L_p − L_d) > C_infra
M: 生命周期内变更次数；V_p / V_d: 单次变更的验证成本；
L_p / L_d: 期望错误损失；C_infra: 原子 / DSL / 评测集的一次性投入
```

工程上可操作的判断：**规则数 > 10 条、跨实例高频、需要回测 / 审计 / 排名可比 → D 明确占优；
一次性分析、低频、由人兜底 → P 足够。**

**工程维度小结**：

| 维度 | P / S | D | 优势成立条件 |
|---|---|---|---|
| 验证 | 统计评测、flaky、难硬门禁 | 确定性测试、可硬门禁 | 有验收帧与 property 生成 |
| 变更 | 爆炸半径不可见 | diff / 影响面 / shadow / 回滚 | 表达式与原子版本化 |
| 运行 | 每次模型调用 | 生成摊销 + 微秒求值 | 生成在作者态 |
| 可用性 | 依赖模型服务 | 离线可跑 | 执行层与模型解耦 |
| 排障 | 文本 + 推理链 | 中间量 + 逐节点 | 中间量已透出 |
| 安全 | 注入面大 | 白名单、无 IO | 生成与执行分离 |
| 知识资产 | prose，随人走 | 契约 + 规则，可评审 / 复用 | 有权威评审流程 |
| 前期成本 | 低 | 高 | N 与变更频率足够大才回本 |

#### D. prompt/skills 的真实优势（对称分析）

1. **time-to-first-value**：零基建，当天可用；
2. **开放语义 / 定性判断**：管理层可信度、政策冲击、叙事强弱——强行写成公式是**伪精确**（§9.10）；
3. **没有原子缺口问题**：不存在「库里没有这个算子」；
4. **意图可读**：非工程师能直接看懂、直接改；
5. **适合探索**：假设生成、草稿、一次性分析脚本；
6. **它是 D 的必要前端**：意图解析、原子选择、澄清问题、结果解释——去掉它，D 退化成「人写规则」。

所以正确结论不是「用 D 取代 P/S」，而是：**P/S 从「执行器」降级为「编译器前端」**，把数值与判定交给
确定性层。

#### E. 判据：什么时候 prompt/skills 就够

| 场景特征 | 推荐 | 理由 |
|---|---|---|
| 低频 + 人直接读结果 + 错误可当场发现 | P/S | 验证成本低于 D 的基建成本 |
| 定性 / 开放判断 | P/S | 公式会制造伪精确 |
| 高频、跨实例、结果进决策链 | D | 方差与结构错不可接受 |
| 需要回测 / 校准 / 网格 | **只能 D** | P 的成本与非确定性不可承受 |
| 需要横截面可比（排名） | D | 统一口径，避免隐性不一致 |
| 需要审计 / 复盘 / 回滚 | D | 可回放、可 diff、可版本化 |
| 需要模型升级后行为不变 | D | 执行层与模型解耦 |
| 需要快速验证一个新想法 | P/S | 先探索，跑通后再固化成原子 / 规则 |

两个反模式：**用 D 做定性判断**（伪精确，把判断力浪费在编公式上）；**用 P 做高频数值决策**
（把方差当能力，出问题无法定位）。

#### F. 把争论变成数据：对照实验

在同一批规则上做 P vs D 对照（建议 3 条：纯数值一条、带口径判断一条、有真实 bug 史一条）：

| 指标 | 含义 | 可证伪假设 |
|---|---|---|
| 结构错率 | 单位 / 除零 / 越界 / 语法 | H1：D ≈ 0，P > 0 |
| 语义错率 | 与人工总裁决比对 | H2：**两者相当**（D 不会自动更懂业务） |
| 同输入方差 | 同帧跑 10 次的结果差异 | H3：D = 0，P > 0 |
| 跨措辞一致性 | 同义需求改写后的输出 | H4：P 更差（D 由前端 LLM 吸收） |
| 跨实例一致性 | 同一规则扫 N 个标的 | H5：D 一致，P 的隐性阈值会漂 |
| 变更后回归时间 | 改一条规则到可上线 | H6：D 更短（定向测试 vs 全量评测） |
| 人工复核时间 | 每帧人工确认耗时 | H7：D 更短（有中间量可查） |
| 单次决策成本 | token + 延迟 | H8：D 更低（生成摊销） |

**决策规则**：若 H2 成立（语义错率相当）而 H1 / H3 / H6 / H7 成立，则 D 的收益来自「可验证性」而非
「更聪明」——这正是它值得做的理由；若 H2 显示 D 更差，先修**原子语义**，不要回退到 P。

#### G. 结论

1. **P/S 优化的是「第一次做对的概率」，D 优化的是「错了能被发现、对了能被复现、改了能被回滚」**——
   前者是抽样问题，后者是验证问题，不能互相替代。
2. **结果维度的优势**集中在四件事：结构错清零、运行方差归零、可回测校准、横截面口径一致；
   **不是**「语义更准」。
3. **工程维度的优势**集中在四件事：验证从抽样变证明、变更爆炸半径可控、运行成本与延迟可忽略、
   审计与安全边界清晰。
4. **代价必须对称承认**：前期基建、原子缺口，以及最重要的**系统偏差**风险——D 的前提是「原子语义
   被契约测试钉死」，否则它只是把随机错误换成一致性错误。
5. 最终判据只有一条：**这类错误是否昂贵且重复**。昂贵且重复 → 把计算下沉到确定性层；廉价且一次 →
   prompt/skills 更快更省。

## 11. 术语表

| 术语 | 含义 |
|---|---|
| 方向分（direction score） | 每轴压到 `[-1,1]` 的符号化强度，正 = 对结论有利 |
| 模式证据（pattern evidence） | 每个状态由「门控 × 支撑 × 否决」算出的非负分数 |
| cap（可达上限） | 该状态公式在输入域上的最大值，结构性常量，不参与调参 |
| 归一化证据 | `clip01(evidence / cap)`，状态间可比、∈[0,1] |
| 软状态（soft state） | 状态的概率分布 `P` + argmax 锚点 + 熵 + drift，而非硬标签 |
| `P_top` | 分布最大值，即「状态确信度」；不是概率、不是后验 |
| `H_norm` | `H / ln(K)`，分布离散度，∈[0,1] |
| 门控（gate） | 决定「现在是不是这个模式的时机」的 `[0,1]` 因子，通常放在领先轴 |
| 支撑（support） | 同一模式内部同向证据的加权和 |
| 否决（veto） | 把「看起来像但语义不对」的帧压掉的乘性因子 |
| 顶背离（adverse divergence） | 价格仍强而基本面与预期同时实质恶化；`severity = sf·se·t_up` |
| 顺序哲学（order） | `etf` = 预期→价格→基本面；`tef` = 价格→预期→基本面；只改门控落点 |
| 迁移合法性 | 相邻前进/反向降级/`reopen` 合法，跳级非法 |
| 影子模式（shadow） | 算但不生效的新口径，用于积累语料与预演 |
| 变异杀伤（mutation kill） | 故意改错实现，断言测试能变红，用以证明断言有判别力 |
| 验收帧（acceptance frame） | 固定输入 → 固定输出的锚点，语义变了它必须变 |
| 原子（atom） | 带契约的纯函数算子：签名/值域/缺失口径/单调性/示例/版本一次声明 |
| 表达式 DSL | 受限、类型化、可 diff 的表达式语言；LLM 只在这里写结构，不写代码 |
| 契约测试（contract test） | 由原子契约自动生成的 property test（单调、值域、缺失、边界） |
| 结构化错误 | 编译器返回的机器可读错误（code/path/expected/actual/suggestion/candidates），用于 LLM 迭代收敛 |
| `request_new_atom` | Agent 的诚实出口：现有原子无法表达时显式上报，而不是用近似原子硬凑 |
| 评测集（eval set） | NL 需求 → 期望表达式的样本集，量化 typecheck / fixture / 语义 / 「该说不会」四类指标 |
| 偏差型错误 / 方差型错误 | 前者所有实例同向错（系统偏差），后者随机分布；DSL 把误差从方差型推向偏差型，因此更依赖语义验收 |
| 硬门禁（hard gate） | 确定性测试，不过即阻止合并；与只能「降低不知道」的统计评测相对 |
| 统计评测（statistical eval） | 用样本估计准确率的验证方式，检出能力受样本量与 flakiness 限制 |

## 附：一句话总结

**把「数值 → 状态」建模成一件可审计的事**：先统一符号压成方向分，再用「门控 × 支撑 × 否决」为每个状态
独立写证据，除以可达上限让状态可比，softmax 成软状态分布；argmax 只定动作类型，分布期望定力度，
阈值与赔率定门槛；所有缺失显式留痕，所有不变量用测试钉死，所有参数走校准规程，所有新版本可一行回滚。
同一套原子也可以交给 LLM 组合成表达式来覆盖长尾需求（§9），但那时准确性来自**受限 DSL 与门禁**，
而不是模型本身；泛化能力来自**原子库的闭包**，而不是更长或更聪明的提示词。
