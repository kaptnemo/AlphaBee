# 黄金帧工厂：实验性设计（Golden Frame Factory, Experimental）

> 状态：**实验性设计稿（沙箱、非生产、可随时终止）**
> 定位：验证一个假设——能否用"当前帧 → 情景投影 → 按时核对"这条生产链路，**自举**出一套可用的评估资产（黄金帧）。
> 关联：`docs/design/BACKTEST_SNAPSHOT_REPLAY_DESIGN.md`（输入冻结/回放/版本兼容）、`docs/roadmap/AGENT_STRATEGY_ROADMAP.md` W2/W5。
> 纪律：本文只做设计与实验计划，不含实现；实验代码不得进入生产链路，只读消费生产产物。

---

## 0. 为什么把它当"实验"而不是"工程"

这是一个**大工程**的种子，但不应一开始就按大工程做。原因：

- "观点没有 ground truth"是本质问题，不是靠堆代码能解决的；
- 评估资产的价值取决于**标签质量与独立性**，而这两点需要先小规模验证；
- 全量快照、全自动策展、统计校准都需要长期语料，早期投入产出比低。

因此本实验只回答一个问题：**"生产过程能否以可接受的成本，产出可用的黄金帧候选？"**
失败就停，成功再扩。

## 1. 核心假设（实验要验证的东西）

| 编号 | 假设 | 验证方式 | 失败即停止的信号 |
|---|---|---|---|
| H1 | 生产过程能自动/半自动产出 A/D/E 类黄金帧候选 | 统计候选数量、覆盖的失败模式 | 候选全是重复的正常样本 |
| H2 | "按时核对"的残差能区分**输入假设错 / 规则错 / 版本错** | 人工抽查归因一致性 | 无法归因，残差无诊断价值 |
| H3 | 小规模专家评分卡 + 受控 LLM judge 的一致性可接受 | Cohen's kappa / ICC | kappa 过低（如 < 0.4）且无法改进 |
| H4 | 黄金帧能捕获回归（注入变异会被杀死） | 变异测试 kill rate | 变异杀不死或只能杀 trivial 变异 |
| H5 | 评估闭环能降低重复错误 / 改善校准 | 前后对比、错误复现率 | 评估后错误率无变化 |
| H6 | 成本可接受 | 每案例人工/算力成本、time-to-freeze | 策展成本 > 收益 |

> 实验的目标不是"证明系统很准"，而是"证明**评估资产生成机制**可行"。

## 2. 四个概念的定位与关系

| 概念 | 是什么 | 在评估中的角色 |
|---|---|---|
| **当前帧** | 在 t0 用当时信息算出的状态（state / factor snapshot / artifact） | 黄金帧的**输入+观测输出**（A/B 候选） |
| **情景投影** | 在明确假设下，预测 t1 的状态（条件推演） | 黄金帧的**预注册承诺**（D 前半；合成 E） |
| **按时核对** | 到期后用真实帧与预测帧对比，产出残差/命中标签 | 黄金帧的**标签生成器**（D 后半；E 失败样本） |
| **黄金帧** | 经过策展、标注、冻结、版本化的评估资产 | 用于回归/事实/论证/校准/对抗评估 |

```
        ┌─────────────────────────────────────────────┐
        │  输入快照（frozen inputs, as-of, 版本清单）   │
        └───────────────────┬─────────────────────────┘
                            │
              ┌─────────────▼─────────────┐
              │ 当前帧 (state at t0)       │──► A 确定性黄金帧
              └─────────────┬─────────────┘──► B 事实黄金帧
                            │
              ┌─────────────▼─────────────┐
              │ 情景投影 (scenario → t1)   │──► D 预测黄金帧（预注册）
              └─────────────┬─────────────┘──► E 合成/对抗样本
                            │
              ┌─────────────▼─────────────┐
              │ 按时核对 (t1: 预测 vs 真实) │──► D 校准标签
              └─────────────┬─────────────┘──► E 失败/边界案例
                            │
                     ┌──────▼──────┐
                     │ 策展 promotion │──► 冻结、版本化、分层
                     └──────┬──────┘
                            ▼
                    黄金帧资产（A–E）
```

**一句话**：当前帧是原料，情景投影是承诺，按时核对是标签，黄金帧是**策展后的成品**。
生产帧不等于黄金帧，中间必须有 promotion。

## 3. 分层真值模型（"没有 ground truth"的正确拆法）

| 层 | 评什么 | 真值来源 | 可测量性 |
|---|---|---|---|
| 工程正确性 | 映射、规则、契约、复现 | 确定性 | 高（精确比对） |
| 事实正确性 | 数字、日期、事件、引用 | canonical 事实 / 原文 | 高（claim 核对） |
| 论证质量 | 证据覆盖、反证、可证伪性、一致性 | 评分卡（专家/受控 judge） | 中（区间评分） |
| 校准 | 状态分布/置信度是否可信 | 未来真实状态/结果 | 中（统计） |
| 决策有用性 | 按结论行动是否有效 | 市场结果（统计） | 低（噪声大） |
| 过程合规 | 是否按研究纪律执行 | run trace / 审计 | 高（不变量） |

**核心转换**：不要问"观点是否对"，问四个可操作问题：

1. 事实是否可验证？
2. 论证是否可证伪、证据是否支撑？
3. 预测是否兑现、置信度是否校准？
4. 按它行动是否有效？

## 4. 五类黄金帧（评估资产分类）

| 类型 | 名称 | 形态 | 生成方式 | 主要用途 |
|---|---|---|---|---|
| **A** | 确定性黄金帧 | 冻结输入 + 精确期望输出 | 同版本重算/固定值 | 复现、回归、契约 |
| **B** | 事实黄金帧 | 冻结输入 + claim→正确值 | 事实核对器 + 原文 | 抓幻觉、单位/时点错误 |
| **C** | 论证黄金帧 | 冻结输入 + 专家评分卡（区间） | 人/受控 judge | 证据、反证、可证伪性 |
| **D** | 预测黄金帧 | 冻结输入 + 预注册预测 + 到期真实帧/结果 | 情景投影 + 按时核对 | 校准、命中率、漂移 |
| **E** | 对抗黄金帧 | 已知陷阱 + 期望行为（必须标记/不得断言） | 失败复盘 + 合成情景 | 鲁棒性、防回归 |

生成难度：A/B/E 低-中（可自动化），D 中（需时间积累），C 高（需人）。

## 5. 映射：过程产物 → 黄金帧

| 过程产物 | 可生成 | 还差什么 | 能验证 | 不能验证 |
|---|---|---|---|---|
| 当前帧 + 冻结输入 | A | 期望输出 | 复现/回归/契约 | 结论正确性 |
| 当前帧 + report claims | B | canonical 事实核对 | 数字/日期/引用 | 论证质量 |
| 当前帧 + thesis/insight | C | 评分卡 + 一致性校准 | 证据/反证/可证伪 | 观点对错 |
| 情景投影（预注册） | D 前半 | 到期真实帧、命中定义 | 条件推演一致性；合成鲁棒性 | 情景是否发生 |
| 按时核对（残差） | D 标签 + E 候选 | 独立结果/归因 | 校准/命中/漂移 | 单案例对错 |
| 脚本化情景 | E 合成样本 | `synthetic=true` 标注 | 单调性/边界/覆盖率 | 现实真值 |

## 6. 为什么不能直接拿生产帧当黄金帧

1. **没有期望**：帧只是观测，黄金帧需要期望值/标签。
2. **循环论证**：当前帧、预测帧、真实帧同源分类器；直接比对只测一致性/校准，不测语义正确性。
3. **冻结错误**：未经独立校验会把当前 bug 固化为标准行为。
4. **选择偏差**：只覆盖跑过的股票/时段；需分层与对抗样本。

因此必须有 **promotion**：`candidate → 校验 → 标注期望 → 分层 → 冻结 → 版本化`。

## 7. 黄金帧工厂流程（六步）

### Step 1 Capture（生产）
- 冻结输入快照 + 当前帧 + 执行清单（code/config/schema/model 版本）。
- 产出：A/B 候选。
- 依赖：`BACKTEST_SNAPSHOT_REPLAY_DESIGN.md` 的输入账本。

### Step 2 Predict（情景投影）
- 把每个情景写成**预注册预测契约**（见附录 A）：`target_time`、假设输入、预测分布、失效条件、版本哈希。
- 产出：D 前半候选。
- 纪律：预测先于到期，append-only，不可事后修改。

### Step 3 Verify（按时核对）
- 到期用真实帧与预测帧对比：残差、命中/未命中、校准误差。
- 归因：**输入假设错 / 规则错 / 版本错**。
- 产出：D 标签 + E 失败候选。

### Step 4 Promote（策展）
- 分层抽样：正确 / 错误 / 边界 / 对抗 / 稀有情景。
- 附期望与归因；独立校验（专家或独立 oracle）。
- 标注来源：`real` / `synthetic` / `reconstructed` / `frozen-bug`。
- 产出：`candidate → verified`。

### Step 5 Freeze（冻结）
- 内容哈希 + schema/version + 不可变。
- 进入评估集；保留退役机制。
- 产出：黄金帧资产。

### Step 6 Evaluate（使用）
- A 回归、B 事实、C 评分卡、D 校准、E 对抗。
- 每次规则/参数/模型变更跑黄金集，产出变更影响报告。

## 8. 独立性原则（否则黄金帧会自证）

| 独立性 | 要求 | 不满足的后果 |
|---|---|---|
| **输入独立** | 黄金帧输入来自冻结快照，不随生产数据漂移 | 同一 bug 被反复"确认" |
| **标签独立** | D 的结果标签来自外部（真实数据/结果），不由被测分类器再算一遍 | 校准指标虚高 |
| **Oracle 独立** | C 的评分来自人/受控 judge，且与人校准过 | LLM judge 自偏好、冗长偏好 |

**特别说明（循环性）**：若 D 的"真实帧"仍由同一分类器计算，则残差主要反映**输入假设误差**，而非规则正确性。这依然有价值（诊断情景假设），但指标命名必须区分：
- `input_error`（假设 vs 实际证据）
- `rule_error`（同输入下规则/版本差异）
- `outcome_error`（外部结果）

---

## 9. 情景投影的特殊价值：补覆盖率

现实稀有情景（如"预告大幅下修 + 价格新高"）可能很久才出现。脚本化情景可**合成**这些案例，用于：
- 单调性/边界/对抗测试（E）；
- 论证质量与失效条件检查（C）。

但必须标注 `synthetic=true`，**不得用于 accuracy/校准指标**——它们是逻辑推演，不是现实真值。

## 10. 最小可行实验（MVP）

### 10.1 范围
- 标的：1–3 只，覆盖至少 1 个财报季。
- 预测：20–50 条预注册预测（含情景与失效条件）。
- 黄金集：A 类 20 条、B 类 10 条、E 类 10 条；C 类 10 条（2 名评审）。
- 周期：1 个季度。
- 环境：沙箱，只读生产产物，不改生产路径。

### 10.2 交付物
1. 预测账本（append-only，含契约与哈希）。
2. 核对记录（残差 + 归因分类）。
3. 黄金帧清单（A–E，含来源与状态）。
4. 一份实验报告：H1–H6 的结论 + 成本 + 失败模式。

### 10.3 成功标准
- 100% 预测有完整契约且不可变。
- 真实帧可从快照复现（L1 逐字节一致）。
- 残差能归因为 input/rule/version 三类，人工抽查一致率 ≥ 70%。
- 至少产出 10 个 E 类失败/对抗案例。
- C 类评分者一致性达到可接受阈值（kappa ≥ 0.6，或说明为何达不到）。
- 注入变异能被黄金集杀死（kill rate 可量化）。

### 10.4 停止标准（kill criteria）
- 真实帧无法从快照复现。
- 预测契约过于模糊，无法判定兑现。
- 残差无法归因，评估无诊断价值。
- 策展成本显著高于收益。
- C 类一致性长期不可接受且无法改进。

> 任一成立即暂停，记录原因，不继续投入。

## 12. 指标（实验期只取少量）

- **覆盖**：A–E 各类型数量、失败模式覆盖数。
- **质量**：复现一致率、归因一致率、kappa、变异 kill rate。
- **成本**：每案例人工分钟、算力成本、time-to-freeze。
- **价值**：重复错误下降、校准改善、回归捕获数。

> 实验期不做统计显著性宣称；样本量不足时只报描述统计与置信区间。

## 13. 风险与红线

| 风险 | 说明 | 红线/缓解 |
|---|---|---|
| 循环论证 | 同源生成与评估 | 标签/oracle 独立；指标分层命名 |
| 冻结 bug | 把错误固化为黄金 | 冻结前独立校验 |
| 选择偏差 | 只覆盖跑过的样本 | 分层 + 合成对抗 |
| 泄露 | 预测/核对用未来数据 | as-of + 快照 + 护栏 |
| 成本失控 | 全量快照/全自动策展 | MVP 限范围；先手动后自动 |
| 法律/版权 | 新闻/研报留存 | 合规评估；只存必要派生物 |
| Goodhart | 优化评分卡而失真 | 多指标 + 结果层 + 定期换题 |

**红线**：实验代码不得写入生产决策路径；不得修改生产帧；不得用未冻结/未校验的数据做黄金标签。

## 14. 阶段计划（实验级）

| 阶段 | 内容 | 退出标准 |
|---|---|---|
| **E0 准备** | 定义预测契约、黄金资产 schema、归因分类；选 1–3 只标的 | 三份模板可评审 |
| **E1 原料** | 冻结输入 + 当前帧 + 预测账本（只读消费） | 20–50 条预测可追溯 |
| **E2 核对** | 到期真实帧 + 残差 + 归因 | 归因一致率可量化 |
| **E3 策展** | A/B/E 自动候选 + C 小规模人工评分 | 黄金集冻结 + kappa 报告 |
| **E4 验证** | 变异测试、回归捕获、成本核算 | H1–H6 结论报告 |

**E0–E2 是必做最小闭环；E3/E4 视结果决定是否继续。**

---

## 15. 非目标

- 不建全量快照/全量回测（那是后续工程）。
- 不追求"观点正确率"或端到端自动评分。
- 不把 LLM judge 当真值。
- 不用单案例市场结果做裁判。
- 不在实验期修改生产决策逻辑。

---

## 16. 开放问题（需 owner 裁定）

1. 预测的**兑现判定**由谁定义（规则/人/市场）？
2. C 类评分卡的维度与权重（证据、反证、可证伪、内在一致…）？
3. E 类"必须标记/不得断言"的期望行为如何标准化？
4. 黄金帧的**退役与轮换**策略（防止过拟合）？
5. 合成情景允许进入哪一层（仅 E/C）？
6. 实验数据保留期与合规边界。
